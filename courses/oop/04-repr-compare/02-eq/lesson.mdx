В уроке о ссылках `==` у двух товаров с одинаковыми названием и ценой давал `False`: по умолчанию свой класс
сравнивается по тождественности, как `is`. Но для кассы «латте за 220» и ещё один «латте за 220» — одно и то
же. Научим объекты сравниваться по смыслу.

## `__eq__`

Оператор `a == b` вызывает метод `a.__eq__(b)`. Объявите его — и равенство будет означать то, что нужно
вашему классу. `is` при этом не меняется: он по-прежнему отвечает, один ли это объект.

<Demo id="eq" title="Товары равны по названию и цене" />

`!=` Python считает сам — как «не `==`», отдельный метод не нужен.

## Чужой тип: NotImplemented

Сравнивать можно с чем угодно: `latte == "Латте"`, `latte == 220`. Но у строки нет атрибутов `name` и
`price`, и такой `__eq__` падает:

<Demo id="foreign" title="Сравнение со строкой ломает __eq__" />

Поэтому `__eq__` сначала проверяет тип другого объекта. Если тип чужой, метод возвращает специальное значение
`NotImplemented` — «я не умею сравнивать с таким». Тогда Python спросит второй объект: `"Латте".__eq__(latte)`,
и если и он не умеет — сравнит объекты по тождественности, как `is`: для двух разных объектов это `False`.

<Demo id="not-implemented" title="Сравнение с чужим типом" />

<Mistake title="return False для чужого типа">
`return False` вместо `return NotImplemented` выглядит так же, пока сравнивают со строками и числами. Но
так класс отнимает слово у второго объекта: если другой класс умеет сравниваться с вашим, его `__eq__` уже не
вызовется. Демонстрация ниже — класс `Ticket` (код из кассы), который знает, какому товару он
соответствует.
</Mistake>

<Demo id="false-vs-ni" title="False не даёт ответить второму объекту" />

Не путайте `NotImplemented` (значение, которое возвращает магический метод) и `NotImplementedError`
(исключение) — это разные вещи.

<Exercise id="drink-eq" title="Равные напитки">
Допишите класс `Drink`: два напитка равны, если у них совпадают цена и название — **без учёта регистра**:
кассиры пишут то «Латте», то «латте». Сравнение с объектом другого типа возвращает `NotImplemented`.

<Hint>Сначала проверьте тип `other`, как в демонстрации; потом сравните цены и названия.</Hint>
<Hint>Регистр убирает метод строки `lower()`: `self.name.lower() == other.name.lower()`.</Hint>
</Exercise>

## `__hash__`: объекты в set и ключи dict

`set` и `dict` находят элементы не перебором, а по **хешу** (hash) — числу, которое вычисляет `hash(x)`. Правило:
**равные объекты обязаны иметь равные хеши**, иначе `set` положит два «равных» товара в разные места.
Поэтому, как только в классе появляется `__eq__`, Python отключает хеш по умолчанию — экземпляр перестаёт
быть **хешируемым** (hashable):

<Demo id="unhashable" title="unhashable type: 'Product'" />

Чтобы вернуть хеш, объявляют `__hash__` и вычисляют его только из атрибутов, которые сравнивает `__eq__` — из
всех или из части, — но не из других: иначе у равных объектов хеши разойдутся. Проще всего — хеш кортежа из
всех сравниваемых атрибутов: `hash((self.name, self.price))`.

<Demo id="hash" title="Product в set" />

Сами числа хешей не важны и меняются от запуска к запуску — важно только, что у равных объектов они равны.

<Exercise id="customer" title="Покупатель по телефону">
Допишите класс `Customer`: покупатели равны, если у них один и тот же телефон `phone` (имя может быть записано
по-разному: «Анна» и «Аня»). Сравнение с другим типом — `NotImplemented`. Добавьте `__hash__`, чтобы
покупателей можно было класть в `set` и делать ключами `dict`.

<Hint>Равенство — только по телефону, а хеш можно считать лишь из того, что сравнивает `__eq__`.</Hint>
<Hint>`__hash__` — `return hash(self.phone)`.</Hint>
</Exercise>

## Почему объект пропал из set

Хеш вычисляется в момент, когда объект кладут в `set`. Если потом изменить атрибут, от которого зависит хеш,
объект окажется «не на своём месте» — `set` его больше не найдёт:

<Demo id="lost" title="Изменили цену — товар пропал" />

<Mistake title="изменяемый объект в set">
Объект, который лежит в `set` или служит ключом `dict`, нельзя менять в тех атрибутах, из которых считается
хеш. Надёжнее всего делать такие объекты **неизменяемыми** (immutable) — как это устроить, покажет урок
о настройках dataclass.
</Mistake>
