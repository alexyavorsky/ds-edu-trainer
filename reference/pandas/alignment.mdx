## Коротко

- Операции между Series и таблицами выполняются **по совпадающим меткам** индекса, а не по позициям. Порядок строк не важен.
- Метка есть только в одном из объектов — в результате `NaN`, а набор меток — объединение обоих.
- Методы `add`, `sub`, `mul`, `div` с `fill_value=0` считают отсутствующее значение нулём.
- `reindex(метки)` приводит объект к нужному набору меток; `align` выравнивает два объекта друг по другу.
- Присваивание Series в столбец (`df["new"] = s`) тоже идёт по меткам. Массив NumPy или список — по позициям.

## Подводные камни

<Pitfall title="Метки не совпали — одни NaN">

Если индексы двух объектов не пересекаются (например, после `reset_index` у одного из них), результат будет из одних `NaN`. Проверьте индексы или переходите к позиционной работе через `to_numpy()`.

</Pitfall>

<Pitfall title="Массив вместо Series">

Массив и список выравниванию не подлежат: значения записываются по порядку. Это удобно, но легко перепутать строки, если порядок разный.
