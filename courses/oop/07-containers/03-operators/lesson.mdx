Деньги удобно складывать плюсом: `Money(220) + Money(140)`. Чтобы так можно было писать со своим классом,
операторы тоже задают магическими методами. Это называется **перегрузка операторов** (operator
overloading) — у оператора появляется смысл для нового типа.

## `__add__`: плюс

`a + b` вызывает `a.__add__(b)`. Метод возвращает **новый** объект — результат сложения. Если тип второго
слагаемого чужой, метод, как и `__eq__`, возвращает `NotImplemented`:

<Demo id="add" title="Вес плюс вес" />

<Mistake title="оператор меняет объект слева">
`a + b` не должен менять `a`: никто не ждёт, что после `total = price + delivery` изменится `price`. Метод
`__add__` создаёт и возвращает новый объект, а `self` и `other` оставляет как есть. Объекты-значения вроде
денег и веса лучше вообще делать **неизменяемыми** — менять их только созданием нового объекта.
</Mistake>

## `__radd__`: когда ваш объект справа

`sum(список)` начинает с нуля: `0 + первый + второй…`. Первое сложение — `0 + Weight(…)`: у числа 0 нет
сложения с весом, его `__add__` возвращает `NotImplemented`. Тогда Python пробует **отражённый** метод
второго объекта: `Weight(…).__radd__(0)` (r — от reflected). Если и его нет — `TypeError`:

<Demo id="sum-error" title="sum не умеет складывать вес" />

Обычно `__radd__` для `sum` устроен так: ноль слева — вернуть себя, иначе — то же, что `__add__`.

<Exercise id="money" title="Деньги складываются">
Допишите класс `Money`: `Money(220) + Money(140)` — это `Money(360)`, слагаемые не меняются. Сложение
с чужим типом — `NotImplemented`. Добавьте `__radd__`, чтобы `sum([Money(220), Money(140)])` давал
`Money(360)`.

<Hint>`__add__`: проверка `isinstance(other, Money)`, затем `return Money(self.rubles + other.rubles)`.</Hint>
<Hint>`__radd__`: если `other == 0` — `return self`, иначе — `return self.__add__(other)`.</Hint>
</Exercise>

## `__mul__` и `__rmul__`: умножение на число

`a * 3` вызывает `a.__mul__(3)`, а `3 * a` — сначала `int.__mul__`, который не умеет, а потом `a.__rmul__(3)`.
Для коммутативного умножения на число `__rmul__` обычно просто вызывает `__mul__`:

<Exercise id="grams" title="Граммы на порцию">
Допишите класс `Grams` (вес в граммах, атрибут `value`): `Grams(18) * 3` и `3 * Grams(18)` — это `Grams(54)`.
Умножать можно только на целое число (`int`); на что-то другое — `NotImplemented`.

<Hint>`__mul__`: `if not isinstance(number, int): return NotImplemented`, затем `return Grams(self.value * number)`.</Hint>
<Hint>`__rmul__` — `return self.__mul__(number)`.</Hint>
</Exercise>

<Quiz id="rmul-quiz">
У класса есть только `__mul__`, а `__rmul__` нет. Что даст `3 * Grams(18)`?

- [ ] `Grams(54)` — Python сам переставит множители
- [x] `TypeError`
- [ ] `54`

<Explain>`3 * Grams(18)` сначала спрашивает `int.__mul__`, он отвечает `NotImplemented`. Потом Python ищет `Grams.__rmul__` — а его нет. Переставлять множители сам Python не будет: для своих типов он не знает, коммутативно ли умножение.</Explain>
</Quiz>
