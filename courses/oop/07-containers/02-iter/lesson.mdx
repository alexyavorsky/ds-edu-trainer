`for p in menu.items` работает, но открывает внутренности меню. Хочется писать просто `for p in menu:` —
и чтобы так же работали `list(menu)`, `sum(...)` и генераторы списков. Для этого объекту нужен метод
`__iter__`.

## `__iter__` и `yield`

`for x in obj` начинается с вызова `obj.__iter__()`. Проще всего написать этот метод с `yield`: функция или
метод, в теле которого есть `yield`, — это **генератор** (generator). Он не возвращает значение один раз, как
`return`, а **выдаёт** значения по одному: `yield` отдаёт очередное значение циклу и замирает до следующего
шага. Когда тело метода закончилось, цикл тоже заканчивается.

В `__iter__` можно и не писать `yield`: достаточно вернуть итератор по внутреннему списку — `iter(…)` (о нём
подробнее ниже). Важно одно — `for` получает новый итератор при каждом обходе:

## Генератор в обычном методе

`yield` можно писать и в обычном методе — тогда метод возвращает генератор, по которому можно пройти циклом.
Это удобно для «выборок» без промежуточных списков:

выдаёт по порядку товары дешевле `price`. Используйте `yield`, а не список.

## Итерируемый объект и итератор

За `for` стоят два понятия. **Итерируемый объект** (iterable) — то, по чему можно пройти: список, строка,
меню с `__iter__`. **Итератор** (iterator) — объект, который выдаёт элементы по одному и помнит, где
остановился. `iter(x)` просит у итерируемого объекта новый итератор, а `next(it)` берёт из итератора
следующий элемент. Когда элементы кончились, `next` выбрасывает `StopIteration` — так `for` узнаёт, что пора
остановиться:

<Demo id="iter-next" title="iter и next вручную" />

Главное отличие: список, строку или меню с `__iter__` можно проходить сколько угодно раз — каждый `for`
вызывает `__iter__` и получает новый итератор. Итератор тоже можно пройти циклом `for` (`iter(it)` возвращает
его самого), но только **один раз**: дошёл до конца — пуст навсегда. Генератор — тоже итератор: результат
`menu.cheaper_than(200)` из упражнения выше хватает на один проход, для второго вызовите метод снова.

<Demo id="one-pass" title="Второй проход по итератору пуст" />

<Mistake title="итератор на один проход">
Если `__iter__` возвращает один и тот же сохранённый итератор (например, `self._it = iter(songs)` в
`__init__`), объект можно пройти только один раз: второй `for` ничего не найдёт, без всякой ошибки.
`__iter__` должен каждый раз отдавать **новый** итератор — так и получается с `yield` или с `return iter(self._items)`.
</Mistake>

<Quiz id="generator-quiz">
`cheap = menu.cheaper_than(200)`. Первый `list(cheap)` дал два товара. Что даст второй `list(cheap)`?

- [ ] те же два товара
- [x] `[]`
- [ ] ошибку `StopIteration`

<Explain>Генератор — итератор: второй проход начинается там, где закончился первый, то есть в конце. `list` перехватывает `StopIteration` сам и возвращает пустой список. Чтобы пройти ещё раз, вызовите `menu.cheaper_than(200)` снова.</Explain>
</Quiz>

<Quiz id="next-quiz">
`it = iter(["латте"])`. Что будет при втором вызове `next(it)`?

- [ ] вернётся `"латте"` ещё раз
- [ ] вернётся `None`
- [x] исключение `StopIteration`

<Explain>Итератор помнит, что выдал единственный элемент. Больше элементов нет — `next` выбрасывает `StopIteration`. Цикл `for` перехватывает его сам, поэтому в цикле вы его не видите.</Explain>
</Quiz>
