В прошлом уроке подкласс либо брал метод базового класса как есть, либо заменял его целиком. Чаще нужно
третье: **дополнить** метод базового класса — сделать всё то же самое и ещё немного. Для этого есть `super()`.

## Свой `__init__` в подклассе

У выпечки, кроме названия и цены, есть вес. Значит, подклассу `Pastry` нужен свой `__init__` с параметром
`weight`. Но переписывать в нём `self.name = name` и `self.price = price` не стоит: это уже умеет `__init__`
базового класса. Вызов `super().__init__(…)` выполняет `__init__` базового класса для этого же экземпляра:

<Demo id="init" title="Pastry с весом" />

`super()` — это «тот же `self`, но методы ищутся начиная с класса, следующего за тем, где написан
`super()`»; пока у класса один базовый класс, это и есть базовый класс. Поэтому `self` в скобки не
передают: `super().__init__(name, price)`.

<Exercise id="drink" title="Напиток с объёмом">
Объявите подкласс `Drink` класса `Product`: `Drink("Латте", 220, 300)` — название, цена и объём `volume`
в миллилитрах. Название и цену пусть записывает `__init__` базового класса. Добавьте метод `per_100ml()` —
цена за 100 мл, округлённая до одного знака.

<Hint>Первая строка `__init__` подкласса — `super().__init__(name, price)`, затем `self.volume = volume`.</Hint>
</Exercise>

<Mistake title="забытый super().__init__">
Если в `__init__` подкласса не вызвать `super().__init__(…)`, `__init__` базового класса не выполнится вовсе:
свой метод **заменяет** метод базового класса. Экземпляр получится без `name` и `price`, и ошибка всплывёт
позже — `AttributeError` при первом обращении к ним.
</Mistake>

## Расширить, а не скопировать

Так же `super()` работает в любом методе: подкласс вызывает версию базового класса и что-то добавляет к её
результату. Если потом формат строки в `Product.label` поменяется, подкласс подхватит изменение сам:

</Exercise>

## Порядок поиска методов: MRO

Куда именно смотрит `super()`? У каждого класса есть **порядок разрешения методов** (method resolution order,
MRO) — список классов, в котором Python ищет атрибуты: сам класс, его базовый класс, базовый класс базового и
так далее. В конце всегда стоит `object` — базовый класс всех классов. MRO хранится в атрибуте `__mro__`:

<Demo id="mro" title="MRO подкласса" />

`super()` берёт следующий класс в MRO после текущего. Пока у класса один базовый класс, MRO — просто цепочка
вверх. У класса может быть и несколько базовых — **множественное наследование** (multiple inheritance), —
тогда MRO решает, чей метод найдётся первым. В этом курсе оно не понадобится; для начала хватает правила:
один базовый класс, остальное — композицией (модуль 6).

<Quiz id="object-quiz">
Каким классом заканчивается `Product.__mro__` у класса, объявленного как `class Product:` — без базового класса?

- [ ] `Product`
- [x] `object`
- [ ] `type`

<Explain>Класс без базового класса в скобках всё равно наследует от `object` — от него приходят `__repr__` с адресом, `__eq__` по тождественности и другие методы по умолчанию. `type` — класс самих классов, а не их базовый класс.</Explain>
</Quiz>
