## concat: друг под другом

Функция `pd.concat` получает **список** таблиц и ставит их одну под другой:

<Demo id="concat" title="816 + 760 = 1576 строк" />

Строк стало 1576 — но посмотрите на индекс: последняя метка 759, а не 1575. `concat` сохраняет метки каждой
части. У обеих таблиц они шли с нуля, поэтому теперь метки **повторяются**:

<Demo id="index-trap" title="Две строки с меткой 5" />

`loc[5]` вернул две строки — по одной из каждого полугодия. Это почти никогда не то, что нужно. Параметр
`ignore_index=True` нумерует строки заново:

<Demo id="ignore" title="Индекс от 0 до 1575" />

<Mistake title="повторяющиеся метки после concat">
Склейка без `ignore_index=True` не даёт ошибки, но оставляет мину: `loc` по метке возвращает несколько строк,
а присваивание нового столбца из другой таблицы может завершиться ошибкой. Если метки частей — просто номера
строк, всегда пишите `ignore_index=True`.
</Mistake>

<Quiz id="index-quiz">
```python
a = pd.DataFrame({"x": [1, 2]})
b = pd.DataFrame({"x": [3, 4]})
print(pd.concat([a, b]).index.tolist())
```

Что выведет этот код?

- [ ] `[0, 1, 2, 3]`
- [x] `[0, 1, 0, 1]`
- [ ] `[1, 2, 3, 4]`

<Explain>`concat` сохраняет метки каждой таблицы: у `a` это 0 и 1, у `b` — тоже 0 и 1. Метки подряд `[0, 1, 2, 3]` получились бы с `ignore_index=True`.</Explain>
</Quiz>

## Откуда строка

После склейки уже не видно, из какого файла пришла строка. Если это важно, источник записывают в столбец
**до** склейки — например, методом `assign`, который возвращает таблицу с новым столбцом:

<Demo id="source" title="Пометить полугодие и склеить" />

Первая строка вывода — проверка меток атрибутом индекса `is_unique` («уникален ли»): у склейки без
`ignore_index` метки повторяются (`False`), у новой — нет (`True`).

## Если столбцы разные

`concat` сопоставляет столбцы **по названиям**, а не по порядку. Если в одной из таблиц столбца нет, на его
месте окажутся пропуски:

<Demo id="different" title="В феврале появился столбец tips" />

Это удобно — ничего не теряется. Но если столбец в двух файлах назван по-разному (`cups` и `Cups`), pandas
посчитает их разными столбцами, и в обоих будет половина пропусков. После склейки стоит взглянуть на
`isna().sum()`.

<Note title="Не склеивайте внутри цикла">
Писать `result = pd.concat([result, part])` на каждом шаге цикла — плохая привычка: каждый раз таблица
копируется целиком, и на сотне файлов это заметно медленно. Соберите части в список и вызовите `concat`
один раз.
</Note>

## Склейка столбцами

С параметром `axis=1` таблицы ставятся не друг под другом, а **рядом**:

<Demo id="side" title="Рядом — по меткам строк" />

Осторожно: строки сопоставляются не по порядку, а **по меткам индекса**. Если порядок строк в одной
из таблиц изменился, метки уедут вместе со строками — и результат будет прежним, а не таким, как лежат строки:

<Demo id="side-trap" title="Олег стоит первым, но по-прежнему попал в строку 1" />

Здесь это сработало в нашу пользу: менеджеры остались при своих городах. Но если у таблиц индексы не связаны
между собой — например, обе были отфильтрованы по-разному, — склейка по меткам соединит случайные строки.
Поэтому таблицы с общим признаком соединяют не через `concat`, а по ключу — методом `merge`. О нём следующий
урок.

## Итоги

- `pd.concat([a, b], ignore_index=True)` — таблицы друг под другом, индекс заново.
- Столбцы сопоставляются по названиям; чего нет — заполняется `NaN`.
- Источник строки записывайте в столбец до склейки.
- Много файлов: собрать список, склеить один раз.
- `axis=1` ставит таблицы рядом по меткам индекса; для соединения по смыслу нужен `merge`.
