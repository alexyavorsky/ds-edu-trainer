## Что проверено и верно

- 3.5 `rotate`: `letter` — действительно «Г»; эталон `letter.T[:, ::-1]` = `[[1,1,1,1],[0,0,0,1],[0,0,0,1]]` —
  поворот по часовой, «перекладина уходит вниз по правому краю» — верно. Другое решение `letter[::-1].T` даёт
  то же. Проверка ловит: не массив, неверную форму (`letter[::-1]` и т. п.), «только `.T`», поворот против
  часовой (`letter.T[::-1]`, `np.rot90(letter)`, `letter[:, ::-1].T`). Копия чужой картинки больше не проходит.
  Вывод демо `final` (████ / ···█ / ···█) совпадает с эталоном.
- 8.4 `cube-weeks`: `np.arange(1, 29).reshape(2, 14).reshape(2, 2, 7)` → `(2, 2, 7)`, первый ряд — 1…7 и 8…14,
  как в output.json. Готовых `filled.reshape(3, 4, 7)` и `axis=2` в тексте и первой подсказке больше нет;
  шаг остаётся решаемым по аналогии с демо и описанию осей.
- 9.2 `two-cols`: строка 0 — 2·180+250+3·60 = 790 и 2·250+300+3·50 = 950, как в тексте и выводе. `price_cost`
  появляется только в упражнении, во всех его частях (эталон, заготовка, другое решение, ошибка).
- 9.3 `to-many`: разности `[[-1,-1],[1,0],[4,4]]`, длины √2, 1, √32 ≈ 5.657 — верно; «урок о векторизации» —
  Пифагор действительно там (`np-vectorize`).
- 9.4: новая формулировка условия единственности верна для квадратной системы; в демо `[690, 1380]`
  согласован с первым чеком, так что «подходит сколько угодно пар цен» — верно. Итоги согласованы с Mistake.
- 1.4 `int32` в браузере — согласовано с заметкой урока `02-shape/03-dtypes`.
- 5.3 `n` против `n − 1` — верно, согласовано со справочником `reference/numpy/statistics.mdx`.
- 6.4 четыре массива: `cost`, `markup` (столбцы через `newaxis`), `amounts`, `volume_discount` — верно.
