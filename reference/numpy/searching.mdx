## Коротко

- `np.searchsorted(a, v)` — бинарный поиск: индекс, куда вставить `v`, чтобы `a` остался отсортированным. Работает за O(log n).
- Массив `a` **должен быть отсортирован** по возрастанию — это никто не проверяет.
- `side="left"` (по умолчанию) ставит перед равными, `side="right"` — после. Разница между ними — число вхождений `v`.
- `v` может быть массивом: ответ для каждого элемента сразу. Так значения раскладывают по интервалам.
- `np.partition(a, k)` ставит на место `k`-й по величине элемент: слева меньшие, справа большие, но **без сортировки** внутри частей. Это быстрее полной сортировки, если нужны только top-k.

## Синтаксис

<Syntax code={`np.searchsorted(a, v, side="left")
np.partition(a, k)           # k-й элемент на своём месте
np.partition(a, -k)[-k:]     # k наибольших (в произвольном порядке)
np.argpartition(a, k)        # то же, но индексы`} />

## Подводные камни

<Pitfall title="Неотсортированный массив">

`searchsorted` не проверяет порядок и возвращает какое-то число без ошибки. Если данные не отсортированы, сначала `np.sort` или используйте `argsort` + `sorter=`.

</Pitfall>

<Pitfall title="partition не сортирует части">

После `partition` упорядочен только один элемент — k-й. Если top-k нужны по порядку, отсортируйте эти k элементов отдельно, как в примере выше.

</Pitfall>
