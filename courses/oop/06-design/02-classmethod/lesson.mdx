Товары в кассу часто приходят не по одному вызову `Product("Латте", 220)`, а строками из файла
(`"Латте;220"`) или словарями из формы. Разбирать строку перед каждым созданием экземпляра — неудобно, и
делать это в `__init__` тоже не хочется: тогда обычный вызов `Product("Латте", 220)` перестанет работать.
Нужен второй способ создать экземпляр — **альтернативный конструктор**.

## `@classmethod`

Метод с декоратором `@classmethod` — **метод класса** (class method). Первым параметром он получает не
экземпляр, а **сам класс** — по соглашению этот параметр называют `cls`. Вызывают его через класс:
`Product.from_line("Латте;220")`. Внутри `cls(...)` — то же, что вызов класса, то есть создание экземпляра:

## Почему `cls`, а не имя класса

Метод класса наследуется. Если подкласс вызывает `from_line`, то `cls` — это подкласс, и создаётся
экземпляр подкласса. А `Drink(...)`, записанный внутри метода явно, всегда создаёт `Drink` — даже когда
вызвали `SeasonalDrink.from_line(...)`:

## `@staticmethod`

Иногда функция логически относится к классу, но ей не нужны ни экземпляр, ни класс — например, проверка
формата телефона. Такую функцию объявляют внутри класса с декоратором `@staticmethod` — это **статический
метод** (static method): без `self` и без `cls`. Вызывают его через класс или экземпляр:

## Какой метод выбрать

| Метод | Первый параметр | Когда |
| --- | --- | --- |
| обычный | `self` — экземпляр | работает с данными экземпляра |
| `@classmethod` | `cls` — класс | создаёт экземпляры (альтернативный конструктор) или работает с атрибутами класса |
| `@staticmethod` | нет | вспомогательная функция, которая по смыслу относится к классу |

<Quiz id="which-quiz">
Какой метод нужен для `Order.from_receipt(text)`, который разбирает текст чека и возвращает новый заказ?

- [ ] обычный метод с `self`
- [x] метод класса с `cls`
- [ ] статический метод

<Explain>Экземпляра ещё нет — его только предстоит создать, поэтому `self` неоткуда взять. Метод класса получает класс и создаёт экземпляр вызовом `cls(...)` — и для подклассов тоже. Статический метод мог бы вернуть `Order(...)`, но потерял бы подклассы.</Explain>
</Quiz>
