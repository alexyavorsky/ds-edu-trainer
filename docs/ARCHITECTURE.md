# Архитектура

Личный тренажёр задач по книгам и темам + справочник + интерактивные курсы. Статический сайт (Astro → Vercel),
бэкенда нет.

## Принцип

**Папка = сущность, реестров нет.** Раздел задач — папка с `book.toml`, глава — папка `NN-slug/` с `chapter.toml`,
задача — папка с `meta.toml`. Удалил папку — исчезло с сайта, добавил — появилось.

Раздел задач бывает двух видов (`kind` в `book.toml`):

| поле | книга (`kind = "book"`) | тема (`kind = "topic"`) |
|---|---|---|
| `title`, `code`, `order`, `description` | да | да |
| `direction` | обязателен | обязателен |
| `beta` | необязателен | необязателен |
| `author`, `edition` | `author` обязателен | — |
| `packages` | нельзя: задачи только на стандартной библиотеке | обязателен: `["numpy"]`, `["pandas"]` или `[]` — только стандартная библиотека (ООП) |
| `reference` | — | тема справочника, к которой относятся задачи |
| подпись главы | «Глава 3» | «Раздел 3» |

Главы темы — свои, по видам задач (а не копия разделов справочника); связь со справочником — `refs` задач, с
курсами — `lessons`.

**Направления и «бета».** У разделов всех видов — `book.toml`, `course.toml`, `reference/<тема>/topic.toml` —
поле `direction`: `python` («Python и алгоритмы»: ООП, алгоритмы, «Грокаем»), `data` («Данные»: NumPy, pandas),
`git`, `english`. Главная, `/courses`, `/reference` и выпадающие меню вкладок шапки (Задачи · Курсы · Справочник)
группируют разделы по направлениям в этом порядке; пустые группы не показываются. Порядок и подписи —
`src/lib/directions.ts` (его же значения проверяют валидаторы). `beta = true` — плашка «бета» с пояснением
«раздел новый, возможны неточности» на карточке, в меню, на странице раздела и в навигации всех его страниц;
снимается удалением строки.

Валидатор проверяет импорты (и в `data.py`): в книгах и темах с `packages = []` — только `sys.stdlib_module_names`,
в темах — ещё пакеты из `packages`.
Тема без глав (сейчас NumPy и pandas) показывается карточкой «скоро» и страницей со ссылкой на справочник;
сборка, валидатор и прогресс это допускают. Когда появятся задачи темы, CI должен ставить её пакеты перед
запуском собранных файлов (`requirements-dev.txt`).

```
challenges/<книга>/<NN-глава>/<slug-задачи>/
  meta.toml     метаданные
  task.md       условие; первый абзац — краткое условие (уходит в docstring)
  starter.py    заготовка / код с ошибками / код с # TODO
  solution.py   эталонное решение
  tests.py      функции test_* на чистых assert, docstring = текст ✓/✗
# для type = "complexity" вместо starter/solution/tests:
  code.py       код, сложность которого нужно определить
# необязательно (на сайте не показываются):
  alt_solutions/*.py   корректные, но «неэкономные» решения — обязаны проходить тесты
  mutants.toml         типичные ошибки «найти → заменить» в solution.py — обязаны проваливать тесты
```

Разделы `task.md` «Ограничения» и «Правила» (списки `- …` и `1. …`) попадают в docstring копируемого файла;
Markdown-выделение `**…**`/`*…*` там убирается. «Примеры», «Детали», «Идея алгоритма» остаются только на сайте.

Книга: «Грокаем алгоритмы», **1-е издание** (Питер, 2019) → 10 глав, без отдельной главы о деревьях.
Терминология по книге: «связанные списки», «базовый / рекурсивный случай», «стек вызовов», «опорный элемент».

## meta.toml

| поле | обяз. | описание |
|---|---|---|
| `id` | да | стабильный ключ (localStorage, «Нашли ошибку?»); kebab-case, префикс `code` книги, уникален |
| `title` | да | название |
| `difficulty` | да | `easy` · `medium` · `hard` |
| `type` | да | `implement` · `fix-bug` · `complete` · `complexity` |
| `tags` | да | непустой список строк |
| `hints` | да | список подсказок (может быть пустым), показываются по одной |
| `bugs` | fix-bug | число ошибок, 1–3 |
| `[complexity]` | complexity | `options` (3–5), `answer` (∈ options), `explanation` |
| `order` | нет | порядок внутри главы |
| `refs` | нет | статьи справочника «тема/статья», например `["numpy/broadcasting"]`; валидатор проверяет, что они есть |
| `lessons` | нет | уроки курсов по id из frontmatter, например `["np-first-array"]`; валидатор проверяет, что они есть; на странице задачи — «Справочник: …» и «Урок курса «…»: …» |

Глава в meta не хранится — определяется папкой. TOML выбран вместо YAML, потому что `tomllib` есть
в стандартной библиотеке Python 3.11+: валидатор работает без `pip install`.

## Копируемый блок

Собирается при сборке (не хранится): `docstring` (название, книга → глава, сложность, тип, id, краткое условие;
у задач темы с пакетами — строка «Нужно: numpy (проверено на 2.5.3)» по `requirements-dev.txt`) + [блок «Данные»
из `data.py` и разделитель «Решение»] + `starter.py` + разделитель + `tests.py` + список `_TESTS` + `runtime/runner.py`.

`data.py` (необязательный, до 150 строк) — данные задачи кодом: функции вроде `sample_orders()`, генераторы на
`random.Random(seed)`. В копируемом файле они стоят перед заготовкой — их можно вызвать в своём коде; тесты их
используют. На сайте `data.py` показан свёрнутым блоком «Данные задачи» над редактором и выполняется воркером
перед кодом из редактора в том же пространстве имён (`data` в запросе `kind: 'task'`), так что номера строк
редактора не сдвигаются.
Функции `test_*` — на верхнем уровне (не нужно переотступать tests.py, совместимо с pytest),
под `if __name__ == "__main__":` — только вызов `_run_tests()`. Вывод: `✓ / ✗ описание`, сообщение, «Прошло N из M».

Тесты запускаются только из `_TESTS` — явного списка функций `test_*` верхнего уровня tests.py по порядку (его
дописывает сборка: `validate.py::tests_list` и `bundle.ts::testsList`). Функция `test_…` в коде решения тестом
не становится. Всё, что идёт после кода решения (разделитель, tests.py, `_TESTS`, раннер), — «footer»: его же
выполняет сайт, так что на сайте и в файле работают одни и те же тесты и раннер.

Раннер (`runtime/runner.py`):
- каждый тест — в daemon-потоке с увеличенным стеком (256 → 64 МБ → по умолчанию) и `join(timeout)`; `signal` не используется;
  в Pyodide (`sys.platform == "emscripten"`) потоков нет — тест выполняется напрямую, таймаут обеспечивает страница;
- результат — список словарей `{title, status, message, error_type, line}`, status: `passed · failed · error ·
  not_written · timeout · not_run`; `line` — строка в коде решения, если ошибка в нём (для сайта: `user_file=`);
  `on_start` / `on_result` вызываются по мере выполнения (сайт показывает тесты сразу);
- `MemoryError` (и `OverflowError` «index-sized» — так 32-битный Python в браузере отвечает на `[0] * 10**10`) →
  «не хватило памяти — возможно, создаётся слишком большая структура данных»;
- stdout переключается на UTF-8 (`reconfigure` в try — в браузере и при перенаправленном выводе его может не быть);
- таймаут по умолчанию 2 с, свой — атрибутом `test_x.timeout = 10`, пояснение — `test_x.timeout_hint = "…"`;
- при зависании печатает итог, помечает оставшиеся тесты «не запускался» и завершает процесс `os._exit(1)`;
- `NotImplementedError` → «функция ещё не написана», итог 0 из N (заготовки `implement` — `raise NotImplementedError`);
- тесты с таймаутом ставятся последними — зависание не скрывает результаты остальных;
- глубина рекурсии в тестах ≤ ~300 уровней: на Python 3.10/3.11 `lru_cache` и генераторы списков удваивают счёт глубины.

Логика сборки: `scripts/validate.py::build_bundle` и зеркально `src/lib/bundle.ts`. Шаблон раннера общий — `runtime/runner.py`.

## Валидация — `python3 scripts/validate.py [--book B] [--chapter C]`

- meta: обязательные поля, допустимые значения, нет неизвестных полей, уникальный id (по всем книгам);
- набор файлов соответствует типу, `.py` компилируются, первый абзац `task.md` пригоден для docstring;
- сигнатуры функций starter и solution совпадают (AST); у классов — базовые классы и декораторы класса
  (`@dataclass(frozen=True)`), публичные методы (и магические) с декораторами (`@property`, `@x.setter`,
  `@classmethod`) и сигнатурами; публичный метод решения, которого нет в классе заготовки, — ошибка; то же для
  `alt_solutions/`; `tests.py` не обращается к `.методу`, который есть только в классе решения;
- ≥ 3 тестов, у каждого docstring;
- сборка с `solution.py` проходит все тесты (подпроцесс, таймаут), и как скрипт печатает «Прошло N из N»;
- сборка со `starter.py` запускается и не проходит хотя бы один тест;
- `complete`: в starter есть `# TODO`; `fix-bug`: diff со solution небольшой;
- по главе: 6–10 задач, все три сложности, ≥ 2 типов (предупреждения).

- `implement`: заготовка — `raise NotImplementedError`;
- `alt_solutions/*.py` проходят все тесты, мутанты из `mutants.toml` проваливают хотя бы один;
- самопроверка раннера: бесконечный цикл, бесконечная и глубокая рекурсия;
- `fix-bug`: каждая ошибка по отдельности ловится тестами (перенос строки считается одной ошибкой);
- тесты не обращаются к функциям, которые есть только в solution;
- синтаксис всех `.py` совместим с Python 3.10;
- эталон и `alt_solutions/` — без устаревшего API: `DeprecationWarning`/`FutureWarning` (и `SettingWithCopyWarning`
  pandas) во время тестов — ошибка теста;
- `data.py`: компилируется, импорты как у задачи, ≤ 150 строк, имена не пересекаются с заготовкой и тестами;
- `refs` и `lessons` ссылаются на существующие статьи и уроки.

`--bundle <папка> [--solution]` печатает собранный файл, `--export <папка>` собирает файлы эталонов, альтернатив
и самопроверок раннера для `scripts/run_bundles.py` (стандартная библиотека, Python 3.10+).

CI (`.github/workflows/tasks.yml`): валидатор на 3.12 → экспорт → матрица Windows/macOS/Linux × Python 3.10–3.14
запускает все файлы; отдельно — сверка сборок сайта, `astro check` и `astro build`.

## Приёмы в тестах

Тесты самодостаточны (копируются в один файл), поэтому вспомогательные классы объявляются в `tests.py` задачи:

- `_Tracked(list)` — считает чтения элементов; проверяет O(log n) у бинарного поиска;
- `_Budget(list, limit)` — бюджет чтений: медленное решение падает сразу с понятным сообщением, а не зависает;
- счётчики вызовов/сравнений (`is_bad`, `_Rank(int)`) вместо замеров времени, где это возможно;
- проверка «решено рекурсивно» (только глава «Рекурсия») — граф вызовов по коду решения: засчитываются вложенные
  и вспомогательные функции и взаимная рекурсия; пропускается, если исходник недоступен (REPL). Запреты вроде
  «без sorted/bisect/heapq» — только в условии, тестами не проверяются;
- лимиты счётчиков — с запасом ×2–×3 от идеального решения и с большим отрывом от наивного; сообщение называет
  лимит и вероятную причину; тест производительности проверяет и сам ответ;
- в тестах нет вспомогательных функций, которые фактически решают задачу — только заранее посчитанные ответы;
- жадные / NP / несколько верных ответов — проверяется допустимость (покрытие, ограничения, жадное правило), а не совпадение;
- float — только `math.isclose`.
- **Глубина рекурсии — с запасом под Safari.** В браузере рекурсия, проходящая через C (`functools.cache` /
  `lru_cache`, `sum` / `min` / `max` по генератору, `map`), тратит стек WebAssembly, а он в Safari маленький:
  `@cache` выдерживает ~60 уровней, `@cache` + `min(генератор)` — ~40, `sum(генератор)` — ~100 (Chrome — в 3–4
  раза больше; обычная рекурсия Python → Python везде до 990 уровней и дальше RecursionError). Поэтому там, где
  подходит рекурсия с запоминанием, тесты требуют глубину **не больше 40** (не больше 26, если естественное решение —
  `min(f(s - c) for c in …)`), а вложенность, которую решают через `sum(генератор)`, — не больше 50. Отсечь перебор
  без запоминания помогают данные с большим ветвлением, а не длина входа. Бюджет проверяет
  `scripts/validate_browsers.ts` (`MEMO_DEPTH`).
- **Глубокие структуры в тестах разбираются вручную.** Список вложенностью в тысячи уровней (или длинная связанная
  цепочка объектов) освобождается рекурсивно, и в браузере это переполняет стек уже на ~1500 уровнях. Тест держит
  такую структуру в переменной и в `finally` разбирает её циклом по одному уровню (образец — `_free` в
  `03-recursion/flatten-deep/tests.py`).
- **Задачи по NumPy и pandas не зависят от разрядности.** Python в браузере 32-битный: целые по умолчанию `int32`
  (локально — `int64`), `np.intp` тоже 32-битный, порядок `set` другой. Тесты проверяют значения
  (`np.array_equal`, `assert_frame_equal(..., check_dtype=False)`, `.tolist()`), а не конкретный dtype, если dtype
  не тема задачи; не сравнивают repr и сообщения, где печатается dtype; размеры в байтах — только отношениями.
  В WebAssembly нет предупреждений о делении на ноль (`RuntimeWarning`) — не проверяйте их появление.

## Сайт (Astro)

```
src/
  content.config.ts        коллекции books / chapters / challenges / topics / reference + схемы Zod
  lib/paths.ts             где лежит контент: корень репозитория или EDU_CONTENT_ROOT (образцы tests/platform)
  lib/directions.ts        направления (порядок групп, подписи) и пояснение к «бета»; lib/nav.ts — меню шапки
  lib/challenges.ts        собственные loader'ы: читают challenges/ и reference/, в dev следят за файлами
  lib/bundle.ts            сборка копируемого .py (зеркало validate.py::build_bundle)
  lib/content.ts           выборки и сортировка для страниц
  lib/labels.ts            русские подписи, Telegram
  scripts/progress.ts      «Решено» в localStorage, обновление прогресса на странице
  components/              Header, Footer, BugReportLink, Badge, Breadcrumbs, ProgressBar, ChapterCard,
                           ChallengeList (фильтры + поиск), CodeBlock (Shiki + копирование), Hints,
                           SolutionReveal, SolvedToggle, ComplexityQuiz, PrevNext, reference/*
  pages/                   /  ·  /[book]  ·  /[book]/[chapter]  ·  /[book]/[chapter]/[task]  ·  /reference/…
```

- Подсветка Shiki — при сборке, без клиентского JS; интерактив — небольшие скрипты на TS без фреймворка.
- «Решено» и прогресс — localStorage (`edu:solved:v1`) по id; фильтры и поиск — на клиенте по data-атрибутам.
- «Нашли ошибку?» → `https://t.me/yavorsky1000?text=…` с id задачи и адресом страницы; текст копируется в буфер.
- `npm run check:bundles` сверяет TS-сборку с Python-сборкой по всем задачам (должны совпадать байт в байт).
- Деплой: Vercel определяет Astro сам (`astro build` → `dist/`), настройка не нужна.
- **Образцы платформы** — `tests/platform/` (challenges/, reference/, courses/ той же структуры): тема справочника
  без пакета, задачи без пакетов и с пакетом, курс без пакета. Переменная `EDU_CONTENT_ROOT=tests/platform`
  подменяет корень контента у сайта и всех валидаторов; `npm run check:platform` (`scripts/validate_platform.ts`)
  прогоняет на образцах все валидаторы и сборку во временную папку. На сайт образцы не попадают.

## Справочник

Темы двух видов: по пакету — NumPy 2.5.3 и pandas 3.0.6 (версии зафиксированы в `requirements-dev.txt`, указаны в
`topic.toml`) — и на стандартной библиотеке (ООП, алгоритмы): `python = "3.10"` вместо `package`/`version`,
свой `prelude.py`, в шапке — «Python 3.10+».
План и оглавление с уровнями — [REFERENCE_PLAN.md](REFERENCE_PLAN.md).

```
reference/
  prelude.py              выполняется перед каждым примером: импорты np/pd, настройки отображения, matplotlib Agg
  <тема>/prelude.py       свой prelude темы — вместо общего (у тем без пакета: пустой или только stdlib-импорты)
  <тема>/topic.toml       title, summary, direction, [beta], order, [[sections]] с порядком статей;
                          тема по пакету — package, version, docs; без пакета — python = "3.10" (docs по желанию)
  <тема>/<статья>.mdx     текст статьи; frontmatter: title, level, summary, requires, related, functions, docs, kind,
                          practice (id задач); docs обязателен только у тем по пакету
  <тема>/<статья>.py      примеры ячейками «# %% id», под каждой — вывод (пишет валидатор)
public/reference/plots/<тема>/<статья>/<id>.svg   графики примеров (пишет валидатор)
```

- Порядок статей и разделы задаёт `topic.toml`; URL — `/reference/<тема>/<статья>`, id — `<тема>/<статья>`
  (он же в `refs` задач и в «Нашли ошибку?»). Имя `index` запрещено: glob-loader считает его страницей темы.
- Разделы статьи: Коротко → (свои) → Синтаксис → Параметры → Примеры → Подводные камни; обзорные статьи
  (`kind: overview` — частые ошибки, шпаргалка) имеют свободную структуру.
- Компоненты без import (их передаёт страница): `Syntax`, `Params`, `Setup`, `Example`, `Pitfall`, `VersionNote`,
  схемы `AxisDiagram`, `BroadcastDiagram`, `GroupbyDiagram`, `MeltPivotDiagram`, `StackUnstackDiagram`, `MergeDiagram`,
  `ClassDiagram` (класс, экземпляры, базовый класс, путь поиска атрибута; props `cls`, `base`, `instances`,
  `lookup`) и `MroDiagram` (ромб и порядок MRO; props `top`, `left`, `right`, `bottom`) — они же доступны в уроках.
- «Задачи по теме» под статьёй: задачи из `practice` и задачи, у которых статья в `refs`, с отметкой «решено».
  `<Example>` находит файл примеров по `Astro.locals.referenceArticle` (Astro 7 не применяет remark-плагины к MDX).
- Флаги ячеек: `[raises=Ошибка]` — пример обязан упасть так; `[warns]` — допустимы предупреждения;
  `[deprecated]` — показывает устаревший API и обязан выдать Deprecation/FutureWarning; `[norun]` — только синтаксис;
  `[timing]` — замер времени. В остальных примерах `DeprecationWarning`/`FutureWarning` — ошибка валидатора.
- Адрес объекта в выводе (`<… object at 0x…>`) — ошибка валидатора: он меняется от запуска к запуску.
- Тема без пакета проверяется в CPython той же версии, что Python в Pyodide (3.14; берётся из
  `node_modules/pyodide/pyodide-lock.json`): тексты ошибок Python различаются между версиями.
- Вывод не должен зависеть от машины (CI — Linux, разработка — macOS). Поэтому в примерах: результаты линейной
  алгебры округлены, порядок собственных значений `eig` задан сортировкой; память — в МБ с округлением или отношением
  (`before // after`), а не в байтах с индексом; `memory_usage` — с `index=False`.
- Замеры времени (`[timing]`): вывод снимается один раз и хранится с машиной и датой —
  `[timing=2026-09-29, machine=Apple M4 · macOS · Python 3.14]`, на сайте подпись «замер на …». При проверке
  пример выполняется, но числа не сравниваются — только текст вокруг них. Переснять: `--retime`.
- Графики: фигуры matplotlib, открытые после примера, сохраняются в SVG в цветах сайта (прозрачный фон, шрифт
  DejaVu Sans из matplotlib, `svg.hashsalt` и без даты — файл одинаковый при каждом запуске) и сравниваются
  с сохранёнными. Объект осей в текстовый вывод не попадает — `<Example>` показывает картинку.
- Кнопка «Копировать» копирует самодостаточный код: импорты + setup + пример. Импорты np/pd добавляются только
  у тем с общим prelude; тема со своим prelude импортирует нужное в коде примера.
- Выполнение примера — `runtime/reference_exec.py`: его импортирует валидатор, и он же выполняет примеры в браузере.
- Поиск — свой индекс `/reference/search.json`, строится при сборке, грузится при первом фокусе на поле.
  Слова индекса и запроса приводятся к основам (`src/lib/stem.ts`: отрезается одно типичное окончание, основа
  не короче 3 букв), совпадение — по началу основы. Вес: заголовок > функции > разделы > описание > текст.
- Навигация статьи: боковое оглавление темы (на узком экране — выдвижная панель), «На этой странице» справа
  (при ширине меньше 1180 px — раскрывающийся блок над статьёй), «назад / далее» по порядку изучения.

Проверка: `.venv/bin/python scripts/validate_reference.py [--update] [--strict] [тема или тема/статья]` —
структура статей, ссылки, выполнение всех примеров и сравнение вывода и графиков с сохранёнными. `--update`
перезаписывает вывод и SVG, `--retime` переснимает замеры времени, `--strict` — ошибка, если статья из оглавления
не написана (так запускает CI).

## Python в браузере (Pyodide)

Сервера нет: код выполняет Pyodide в Web Worker. Версия — `PYODIDE_VERSION` в `src/lib/python/config.ts`
(там же все лимиты), загрузка с jsDelivr; npm-пакет `pyodide` той же версии нужен только для проверки в Node.js.

```
src/lib/python/
  config.ts      версия Pyodide, коэффициент лимита тестов (×3), лимит примера (10 с), вывод (10 000 строк / 1 МБ),
                 потолок памяти WebAssembly (1 ГБ), пакеты через micropip (openpyxl)
  protocol.ts    сообщения страница ↔ воркер
  engine.ts      ядро воркера: загрузка Pyodide, пакеты, запуск; общее для браузера и Node.js
  worker.ts      Web Worker сайта (engine + исходники runtime/*.py)
  client.ts      страница: один воркер на вкладку, очередь, таймауты, перезапуск после зависания и падения
  packages.ts    какие пакеты нужны примеру справочника
runtime/
  pyodide_driver.py  мост: перехват print (лимит), input() → понятная ошибка, запуск задачи и примера
  reference_exec.py  выполнение примера как ячейки Jupyter — общее с validate_reference.py
src/scripts/python/  editor.ts (CodeMirror 6, отдельный чанк), task.ts (страница задачи), examples.ts (справочник)
```

- **Загрузка.** Воркер создаётся, когда на странице задачи или статьи браузер простаивает (`requestIdleCallback`;
  при экономии трафика — только по нажатию). Пакеты — по необходимости: задачи книг — без пакетов, задачи тем —
  `packages` раздела, примеры — пакет темы и то, что нашёл `packages.ts` (pd → pandas, .plot → matplotlib, …); примеры темы
  без пакета и уроки курса без пакета ничего не грузят. Свой prelude темы страница передаёт в запросе примера.
  prelude.py выполняется блоками по импортам: без pandas блок pandas пропускается.
- **Таймауты.** Потоков в Pyodide нет, поэтому зависший воркер завершает страница (`worker.terminate()`) и
  сразу создаёт новый. Тесту даётся его лимит × `timeoutFactor`, коду решения до тестов — лимит по умолчанию × то
  же; пройденные тесты видны, зависший — с сообщением и `timeout_hint`, остальные — «не запускался».
  SharedArrayBuffer не используется: он требует заголовков COOP/COEP.
- **Память.** `WebAssembly.Memory.grow` ограничен (`memoryLimitMB`): Python получает `MemoryError`, а не съедает
  память вкладки. После `MemoryError` воркер пересоздаётся — WebAssembly не отдаёт память обратно.
- **Падения.** onerror / onmessageerror / аварийная остановка Pyodide (переполнение стека WebAssembly при очень
  глубокой рекурсии) → сообщение, новый воркер, следующий запуск работает.
- **Задача.** Код из редактора записывается в `main.py` (номера строк = строки редактора, исходник доступен
  `inspect` — работает проверка «решено рекурсивно»), затем выполняется footer копируемого файла.
  Синтаксическая ошибка или ошибка вне функций — отдельное сообщение со строкой, тесты не запускаются.
- **Безопасность.** Код выполняется только по нажатию «Запустить» / Ctrl+Enter. Никакого запуска кода из ссылок и
  параметров URL — это правило и для будущих функций вроде «поделиться решением».
- **Код в localStorage:** `edu:code:v1:<id>` = `{code, starter}` (хеш заготовки). Заготовка изменилась —
  «Заготовка обновилась»: оставить свой код или взять новую.

Проверка в настоящих браузерах — `node scripts/validate_browsers.ts [chromium|firefox|webkit…]` (нужна сборка
`dist/` и браузеры Playwright): все эталоны и альтернативы в каждом браузере и пробы глубины рекурсии; в CI — на macOS:
там стек WebKit как у Safari (на Linux он в 5–7 раз больше, и бюджет глубины там не проверить).

Проверка — `node scripts/validate_pyodide.ts [--tasks|--reference] [id…] [--update] [--report файл]` (CI, Linux):
эталоны и альтернативы проходят, заготовки — нет; тесты дольше половины лимита браузера — в отчёт. Примеры
справочника выполняются тем же ядром; что в браузере работает иначе, записано в `reference/browser.json`:
`differs` — вывод или график отличается (пометка «в браузере pandas X.Y…»), `unavailable` — не работает (кнопка
неактивна, причина под примером). Расхождение с файлом — ошибка; обновить: `--update`.

## Курсы

Интерактивные курсы: урок — ноутбук из ячеек текста, кода, упражнений и вопросов, одно пространство имён Python
на урок. `course.toml`: `direction`, `beta`, курс по пакету — `package` (numpy · pandas), курс на стандартной
библиотеке (ООП) — `python = "3.10"`: урок ничего не грузит, первая ячейка .ipynb проверяет версию Python,
`output.json` подписан «Pyodide … · Python 3.14», CPython при проверке — той же версии, что в Pyodide.
`concepts = "python"` — сбор понятий для курса по языку: обращения `.x` к своим атрибутам и методам (объявленным
в этом и прошлых уроках) и `x=` в вызовах своих классов и функций — не понятия; понятия — `class`, `class(Base)`,
`def __init__` и другие магические методы, декораторы (`@property`, `@setter`, `@classmethod`, `@dataclass`…),
`super()`, `isinstance()`, `issubclass()`, `hasattr()`/`getattr()`/`setattr()`, `raise`, `raise from`, `yield`,
`import dataclasses` и т. п., магические атрибуты `.__dict__`, `.__mro__`, `.__class__`. `module.toml`:
`practice = "<книга>/<глава>"` — ссылка «Задачи по теме модуля» в программе и в конце модуля. Заготовка
упражнения с `class X:` — цель «class X»: проверка сначала сообщает «класс X не объявлен» или «допишите метод
X.m» (тело метода — `...`). Адрес объекта в сохранённом выводе — ошибка валидатора. Программа, формат, устройство состояния и проверка — [COURSES_PLAN.md](COURSES_PLAN.md).

```
courses/<курс>/course.toml, NN-<модуль>/module.toml, NN-<модуль>/NN-<урок>/{lesson.mdx, lesson.py, output.json}
courses/data/            наборы данных (generate.py, README.md — лицензия CC0)
courses/prelude.py       настройки отображения для сеанса урока
src/lib/courses/         format.ts (разбор lesson.py и lesson.mdx), load.ts (курсы с диска), site.ts (для страниц),
                         notebook.ts (экспорт .ipynb)
src/components/course/   Demo, Exercise, Hint, Quiz, Explain, Note, Mistake, CellOutput, CourseSidebar
src/scripts/course/      lesson.ts (ячейки и состояние урока), progress.ts (прогресс в localStorage)
src/pages/courses/       /courses · /courses/<курс> · /courses/<курс>/<урок> (+ .ipynb) · /courses/data/<файл>
runtime/lesson_exec.py   сеанс урока: ячейки как в Jupyter, проверка упражнения раннером задач — общий для
                         браузера и валидатора
```

- В воркере урок — запросы `kind: 'lesson'` (`prepare` · `cell` · `check` · `quiz`) с id сеанса: новый id —
  новое пространство имён. `python.generation` растёт с каждым новым воркером — по нему урок узнаёт, что
  состояние потеряно (таймаут, падение, нехватка памяти).
- Файлы данных урока воркер берёт один раз (`fetch` с `/courses/data/…`, в Node.js — с диска) и копирует
  в `data/` каждого сеанса.
- Проверка — `node scripts/validate_courses.ts [--update] [--strict]` (Pyodide через `scripts/node-python.ts`
  и CPython через `scripts/course_cpython.py`), в CI — задание «Курсы»; в трёх браузерах уроки с эталонами
  выполняет `scripts/validate_browsers.ts`.
