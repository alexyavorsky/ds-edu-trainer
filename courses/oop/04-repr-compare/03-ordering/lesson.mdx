Список чисел или строк сортируется сам: `sorted([3, 1, 2])`. А список товаров — нет: Python не знает, какой
товар «меньше» другого.

<Demo id="no-order" title="Товары не сортируются" />

Есть два способа научить: объявить «естественный порядок» в самом классе или передать порядок в `sorted`
снаружи — параметром `key`.

## `__lt__`: «меньше»

`a < b` вызывает `a.__lt__(b)` (lt — от less than). Этого одного метода достаточно для `sorted`, `min`, `max`
и метода списка `sort`: `sorted`, `sort` и `min` сравнивают через `<`, а `max` — через `>`, который Python
сводит к `<` второго объекта (подробнее — сразу под демонстрацией):

<Demo id="lt" title="Товары по цене" />

Для чужого типа `__lt__`, как и `__eq__`, возвращает `NotImplemented`. А `a > b` Python сам превращает в
`b < a`, если у `a` нет своего `__gt__`, — поэтому `>` тоже заработал.

<Exercise id="drink-lt" title="Напитки по объёму">
Допишите класс `Drink`: напиток «меньше» другого, если у него меньше объём `volume`; сравнение с чужим типом —
`NotImplemented`. После этого сохраните в `ordered` список напитков из `menu`, отсортированный по объёму,
а в `biggest` — самый большой напиток.

<Hint>`__lt__` устроен как `__eq__`: сначала тип `other`, потом сравнение нужного атрибута.</Hint>
<Hint>`ordered = sorted(menu)`, `biggest = max(menu)` — они сами вызовут `__lt__`.</Hint>
</Exercise>

## `@total_ordering`: все шесть сравнений

Сравнений шесть: `==`, `!=`, `<`, `>`, `<=`, `>=`. `!=` получается из `__eq__`, `>` — из `__lt__` второго
объекта, а вот `<=` и `>=` сами не появятся:

<Demo id="no-le" title="<= не работает" />

Писать ещё два метода не нужно. Декоратор `total_ordering` из модуля `functools` стандартной библиотеки
достраивает недостающие сравнения из `__eq__` и `__lt__`. Декоратор класса ставится над строкой `class`:

<Demo id="total-ordering" title="Все сравнения из двух методов" />

<Exercise id="booking" title="Бронирование столиков">
Объявите класс `Booking` с декоратором `@total_ordering`: `Booking("Анна", "18:30")` хранит имя гостя `name`
и время `time` строкой «ЧЧ:ММ». Брони сравниваются по времени, а при одинаковом времени — по имени: объявите
`__eq__` и `__lt__` (для чужого типа — `NotImplemented`), остальные сравнения достроит декоратор.

<Hint>Сравнивать удобно кортежи: `(self.time, self.name) < (other.time, other.name)` — кортежи сравниваются по первому элементу, при равенстве — по второму.</Hint>
<Hint>Строки «ЧЧ:ММ» с ведущим нулём («09:30») сравниваются как время: `"09:30" < "18:00"`.</Hint>
</Exercise>

<Mistake title="время без ведущего нуля">
Строки сравниваются посимвольно: `"9:30" > "18:00"`, потому что символ `"9"` больше `"1"`. Если время хранится
строкой, оно должно быть в одном формате — «09:30». Надёжнее хранить числа или объекты времени (модуль
`datetime`), но это тема не этого курса.
</Mistake>

## `key=`: порядок снаружи

Не у каждого класса есть один естественный порядок. Товары сортируют то по цене, то по названию, то по
популярности — и ни один порядок не «главный». Тогда в классе ничего не объявляют, а передают `sorted`, `min`
и `max` параметр `key` — функцию, которая для каждого элемента возвращает значение, по которому сравнивать:

<Demo id="key" title="Сортировка с key" />

`lambda p: p.price` — короткая безымянная функция (lambda): то же самое, что `def price_of(p): return p.price`,
только в одну строку и прямо на месте аргумента.

<Exercise id="key-sort" title="Прайс по-разному">
У класса `Product` из демонстрации нет сравнений. Для списка `products` сохраните в `by_name` названия товаров
по алфавиту, в `by_price_desc` — названия от самого дорогого к самому дешёвому, а в `cheapest` — сам самый
дешёвый товар.

<Hint>`sorted(products, key=lambda p: p.name)` даёт товары — названия соберите генератором списка.</Hint>
<Hint>От дорогого к дешёвому — `reverse=True`; самый дешёвый — `min(products, key=lambda p: p.price)`.</Hint>
</Exercise>

<Quiz id="which-quiz">
Кофейня печатает меню то по цене, то по калорийности, то по алфавиту. Как лучше сортировать напитки?

- [ ] объявить `__lt__` по цене, а для остальных порядков — ещё классы
- [x] не объявлять `__lt__`, а передавать в `sorted` нужный `key=`
- [ ] объявить три метода `__lt__` с разными условиями

<Explain>`__lt__` задаёт один естественный порядок — его стоит объявлять, когда он очевиден (время брони, номер версии). Когда порядков несколько и ни один не главный, честнее `key=`: порядок виден прямо в месте сортировки. Три метода `__lt__` в классе невозможны — останется последний.</Explain>
</Quiz>
