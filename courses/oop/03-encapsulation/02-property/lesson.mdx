В прошлом уроке баланс карты читался методом: `card.balance()`. Работает, но выглядит странно — баланс
скорее *атрибут* карты, чем действие. Python позволяет оставить внутренний `_balance` спрятанным и при этом
читать баланс как атрибут, без скобок. Для этого есть **свойства** (property).

## @property

Строка `@property` перед методом — это **декоратор** (decorator): он меняет то, как работает метод под ним.
Метод с `@property` вызывается сам, когда атрибут *читают*, — скобки не нужны. Например, у заказа статус
хранится во внутреннем `_status`, а читается свойством `status`:

<Demo id="property" title="Статус заказа — свойство" />

Снаружи `order.status` выглядит как обычный атрибут, но записать в него нельзя: у свойства есть только
«чтение» — **геттер** (getter). Так получается атрибут **только для чтения**:

<Demo id="read-only" title="В свойство нельзя записать" />

<Note title="Свойство сильнее экземпляра">
В модуле 2 запись `latte.CURRENCY = "$"` создавала атрибут у экземпляра и закрывала атрибут класса. Со
свойством так не выйдет: свойство — особый атрибут класса, который перехватывает и чтение, и запись через
экземпляр. Поэтому `order.status = …` не создаёт атрибут у заказа, а обращается к свойству — и получает
отказ, потому что записи у него нет.
</Note>

Менять статус можно только методами заказа — например, `pay()`, который не даст оплатить заказ дважды.
Так же стоит поступить с балансом подарочной карты.

<Exercise id="balance" title="Баланс карты свойством">
Допишите класс `GiftCard`: сделайте `balance` свойством, которое возвращает `_balance`. Методы `pay` и
`top_up` уже есть.

<Hint>Перед методом `def balance(self):` строка `@property`; внутри — `return self._balance`.</Hint>
</Exercise>

<Mistake title="скобки после свойства">
`order.number()` для свойства — ошибка: `order.number` уже вернуло число, и скобки пытаются вызвать это
число — `TypeError: 'int' object is not callable`. Свойство читают без скобок.
</Mistake>

## Вычисляемый атрибут

Свойство не обязано возвращать сохранённый атрибут — оно может **вычислять** значение каждый раз, когда его
читают. Например, сумма корзины: её не нужно хранить и обновлять при каждом `add`, достаточно посчитать
по товарам:

<Exercise id="cart" title="Сумма и число товаров">
Допишите класс `Cart`: свойство `total` возвращает сумму цен товаров, свойство `count` — число товаров
в корзине.

<Hint>Два метода с `@property`: `return sum(p.price for p in self.items)` и `return len(self.items)`.</Hint>
</Exercise>

Вычисляемое свойство всегда **актуально**: оно считается заново при каждом чтении. Значение, вычисленное
один раз в `__init__`, устареет, как только поменяются данные.

<Exercise id="size" title="Размер по объёму">
Допишите класс `Drink`: свойство `size` возвращает размер по объёму `volume` — до 250 мл включительно `"S"`,
до 350 мл включительно `"M"`, больше — `"L"`. Если объём изменился, размер должен измениться вместе с ним.

<Hint>Свойство с `if self.volume <= 250: return "S"`, затем проверка на 350 и `return "L"`.</Hint>
</Exercise>

## Свойство или метод

<Quiz id="choose-quiz">
Что из этого естественнее сделать свойством, а не методом?

- [ ] `pay(amount)` — оплатить с карты
- [x] `is_empty` — пуста ли корзина
- [ ] `add(product)` — положить товар в корзину

<Explain>Свойство — это «характеристика» объекта: значение без параметров, которое быстро вычисляется и ничего не меняет. `pay` и `add` меняют состояние и принимают аргументы — это действия, то есть методы.</Explain>
</Quiz>

Правило выбора:

| Свойство | Метод |
| --- | --- |
| характеристика объекта: `balance`, `total`, `size` | действие: `pay`, `add`, `remove` |
| без параметров | с параметрами или без |
| ничего не меняет в объекте | может менять состояние |
| вычисляется быстро | может работать долго |

В следующем уроке у свойства появится и запись — с проверкой значения.
