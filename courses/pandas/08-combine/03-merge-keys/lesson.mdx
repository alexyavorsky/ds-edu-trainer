## Ключ называется по-разному

Если ключевой столбец в таблицах назван по-разному, вместо `on` указывают два параметра: `left_on` — название
в левой таблице, `right_on` — в правой.

<Demo id="left-right" title="product_id слева, id справа" />

В результате остались оба ключевых столбца — `product_id` и `id` — с одинаковым содержимым. Лишний обычно
удаляют: `.drop(columns=["id"])`.

## Одноимённые столбцы

В справочниках товаров и клиентов есть столбец `name`: название товара и имя покупателя. Если соединить всё
подряд, pandas различит их окончаниями `_x` и `_y`:

<Demo id="same-names" title="name_x и name_y" />

`name_x` пришёл из левой таблицы, `name_y` — из правой. Понять это через месяц будет невозможно. Свои
окончания задаёт параметр `suffixes` — пара строк для левой и правой таблицы:

<Demo id="suffixes" title="Понятные окончания" />

Окончания добавляются только к столбцам, названия которых **совпали**. Второй способ избежать путаницы —
заранее взять из правой таблицы только нужные столбцы или переименовать их через `rename`.

## Повторы ключа размножают строки

Главная ловушка `merge`. Возьмём очищенный журнал возвратов — 150 строк, по одной на возвращённую позицию:

<Demo id="returns" title="Возвраты: заказ, товар, сколько штук вернули" />

Хотим добавить к строкам заказов число возвращённых штук. Попробуем соединить по номеру заказа:

<Demo id="wrong-key" title="Соединение по order_id" />

Строк стало 2458 вместо 2448, а возвращённых штук — 402 вместо 214. Почти вдвое больше, чем на самом деле.
Посмотрим на один заказ:

<Demo id="wrong-look" title="Заказ 10001 после соединения" />

В заказе 10001 две позиции — кофемолка и травяной сбор. Вернули только кофемолку, 2 штуки. Но соединение шло
по номеру заказа, и возврат «приклеился» к **обеим** позициям: получилось, что вернули и сбор тоже.

Правило: `merge` соединяет каждую строку слева с **каждой** подходящей строкой справа. Если ключ повторяется
с обеих сторон, строки перемножаются.

<Quiz id="dup-quiz">
```python
a = pd.DataFrame({"k": ["x", "x"], "a": [1, 2]})
b = pd.DataFrame({"k": ["x", "x"], "b": [3, 4]})
print(len(a.merge(b, on="k")))
```

Что выведет этот код?

- [ ] `2`
- [x] `4`
- [ ] `1`

<Explain>Каждая из двух строк `a` соединяется с каждой из двух строк `b` с тем же ключом: 2 × 2 = 4 строки.</Explain>
</Quiz>

<Mistake title="после merge строк стало больше">
Если после соединения с `how="left"` строк больше, чем было в левой таблице, — ключ в правой таблице
не уникален. Суммы по такой таблице завышены. Проверьте: `правая.duplicated(subset=[ключ]).sum()` должно быть
нулём, а `len` до и после соединения — совпадать.
</Mistake>

## validate: проверка при соединении

Проверять число строк вручную легко забыть. Параметр `validate` делает проверку частью соединения: вы
сообщаете, какое соединение ожидаете, а pandas останавливается с ошибкой, если это не так.

- `"many_to_one"` — ключ в правой таблице уникален (заказы → справочник);
- `"one_to_one"` — ключ уникален в обеих;
- `"one_to_many"` — уникален в левой.

<Demo id="validate-ok" title="Заказы к справочнику: многие к одному" />

А соединение по одному `order_id` проверку не проходит:

<Demo id="validate-fail" title="Ключ в правой таблице повторяется" />

Ошибка `MergeError` лучше, чем тихо завышенные числа: соединение не состоялось, а в сообщении перечислены
ключи, которые повторяются в правой таблице.

## indicator: откуда строка

Параметр `indicator=True` добавляет столбец `_merge`, в котором записано, нашлась ли пара: `both` — ключ есть
в обеих таблицах, `left_only` — только в левой, `right_only` — только в правой.

<Demo id="indicator" title="Клиенты, у которых есть и нет заказов" />

27 клиентов — `left_only`: в заказах их нет. Это те же «спящие» клиенты из прошлого урока, найденные без
подсчёта заказов. `indicator` удобен для сверки двух списков: что есть в одном и отсутствует в другом.

## Итоги

- Ключи с разными названиями — `left_on=` и `right_on=`.
- Совпавшие названия столбцов получают окончания `_x` и `_y`; свои задаёт `suffixes=("_a", "_b")`.
- Несколько ключей — `on=["a", "b"]`.
- Повторы ключа размножают строки: сверяйте `len` до и после, пишите `validate="many_to_one"`.
- `indicator=True` показывает, у каких строк не нашлось пары.
