## Коротко

- `category` хранит набор допустимых значений (`categories`) и для каждой строки — номер значения (`codes`).
- Для столбцов вроде города, размера, статуса это в разы уменьшает память и ускоряет группировку.
- `ordered=True` задаёт порядок: сортировка и сравнения идут по нему, а не по алфавиту.
- Записать можно только значение из набора категорий; новое сначала добавляют через `cat.add_categories`.
- Категории без строк видны в `value_counts`, но не в `groupby`: там с pandas 3.0 по умолчанию `observed=True`.

## Синтаксис

<Syntax code={`s.astype("category")
pd.CategoricalDtype(["S", "M", "L"], ordered=True)
s.cat.categories, s.cat.codes
s.cat.add_categories([...]), s.cat.remove_unused_categories()
s.cat.rename_categories({...})`} />

<Pitfall title="Когда category не помогает">

Если почти все значения разные (имена, адреса, id), категории хранят те же строки плюс номера — памяти уходит даже больше. Выигрыш заметен, когда уникальных значений намного меньше, чем строк.
