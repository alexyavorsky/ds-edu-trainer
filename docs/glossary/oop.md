# Словарь направления «ООП в Python»

Общий для трёх потоков: справочника (С1, `reference/oop/`), курса (К1, `courses/oop/`) и задач
(З3, `challenges/oop/`). Ревью проверяет тексты и код на соответствие этому файлу. План направления —
[OOP_PLAN.md](../OOP_PLAN.md).

Правило первого упоминания: термин в статье или уроке при первом появлении даётся с английским вариантом
в скобках — «экземпляр (instance)», дальше только по-русски. Имена из кода (`self`, `super()`, `__init__`)
пишутся моноширинным шрифтом и не склоняются: «в `__init__`», а не «в `__init__`’е».

## Термины

| свойство | property | «свойство `area`», «декоратор `@property`» | ✗ «проперти»; ✗ «свойство» в значении «любой атрибут» |

Имена исключений Python и технические имена не переводятся: `TypeError`, `AttributeError`, `NotImplemented`,
`NotImplementedError`. Различать: `NotImplemented` — значение, которое возвращает магический метод
сравнения/арифметики («не умею с таким типом»); `NotImplementedError` — исключение.

## Оформление кода в примерах

**Версии Python.** Код работает на Python 3.10–3.14 (CI задач) и в Pyodide (Python 3.14). Синтаксис —
не новее 3.10. Нельзя в коде примеров, уроков и задач: `typing.Self` (3.11), `except*` и `ExceptionGroup`
(3.11), `add_note` (3.11), `@typing.override` (3.12), `class Box[T]` и оператор `type` (3.12),
`copy.replace` (3.13), расчёт на отложенные аннотации без кавычек (3.14). О них можно сказать текстом
с `<VersionNote>` («с Python 3.12…»), без исполняемого примера.

**Имена.**
- Классы — `CamelCase`, по-английски: `Product`, `Cart`, `LoyaltyCard`, `OutOfStockError`. Методы,
  атрибуты, переменные — `snake_case`, по-английски. Константы класса — `UPPER_CASE`: `MAX_ITEMS = 20`.
- Исключения заканчиваются на `Error` и наследуют от `Exception` (или своего базового `ShopError`).
- Первый параметр метода — всегда `self`, метода класса — `cls`. Другие имена не используем даже для примера.
- Данные в строках — по-русски: `Product("Капучино", 180)`. Сквозной мир — кофейня «Кофейная лавка»
  (как в курсах NumPy и pandas): товары, корзина, заказы, скидки, карты лояльности, склад, оплата.
  `Foo`/`Bar`, `Animal`/`Dog`/`Cat` — не используем; `Point`, `Vector`, `Money`, `Temperature` — можно, если
  предмет задачи сам числовой.
- Внутренние атрибуты — `_x`. Двойное подчёркивание `__x` — только в статье и уроке об именах, где
  объясняется искажение имён, и в задачах на эту тему.

**Аннотации типов.**
- Справочник: в сигнатурах методов — по желанию, коротко (`def total(self) -> int:`); в `<Syntax>` — да.
- Курс: без аннотаций до урока о dataclass (там они — часть синтаксиса полей). После — в полях dataclass
  обязательно, в методах по желанию.
- Задачи: в `starter.py` и `solution.py` — обязательно у публичных методов и функций (это контракт задачи,
  как в существующих задачах). Ссылка на свой класс внутри него — в кавычках: `def __add__(self, other:
  "Money") -> "Money":` (без `from __future__ import annotations`). `X | None`, `list[int]`, `dict[str, int]` —
  да (3.10); `Optional`, `List`, `Dict` из `typing` — нет.

**Стиль.**
- f-строки — да; `%` и `.format()` — нет (кроме статьи о `__format__`, если появится).
- `super().__init__(…)` — без аргументов у `super`.
- Сравнение с `None` — `is None`. Проверка типа — `isinstance`, не `type(x) == …` (кроме примера-ошибки).
- Изменяемые значения по умолчанию (`def __init__(self, items=[])`) — только как пример ошибки с
  `<Mistake>`/`<Pitfall>`; правильно — `None` и создание внутри или `field(default_factory=list)`.
- Импорты — явные и в начале ячейки/файла: `from dataclasses import dataclass, field`,
  `from abc import ABC, abstractmethod`, `from functools import total_ordering`. `import *` — нет.
- Сообщения исключений в своём коде — по-русски: `raise ValueError("цена должна быть положительной")`.
- Отступ 4 пробела, строка до 100 символов, пустая строка между методами.

**Вывод, который зависит от машины, — запрещён** (валидатор сравнивает вывод на macOS, Linux и в браузере):
- repr объекта без своего `__repr__` — `<__main__.Product object at 0x10a3…>`: адрес меняется от запуска
  к запуску. Показываем объект только после того, как у класса есть `__repr__`, или печатаем атрибуты.
  Где урок объясняет, зачем нужен `__repr__`, «плохой» вывод показывается текстом, а не выполняемой ячейкой
  (или ячейкой, которая печатает `type(obj).__name__`).
- `id(obj)`, `hash()` строк и объектов по умолчанию, порядок элементов `set` из строк — меняются от запуска
  к запуску (рандомизация хешей). Тождественность показываем через `a is b` → `True/False`.
- Тексты встроенных сообщений об ошибках различаются в Python 3.10–3.14 (например, у `AttributeError` при
  записи в свойство без сеттера и у `TypeError` при создании экземпляра абстрактного класса). В справочнике и
  курсе они показываются как есть (вывод снимается в Python 3.14, как в браузере); в тестах задач
  сравнивается только тип исключения, не текст.
- `__del__` и сборка мусора — момент вызова не гарантирован; не показываем выполняемыми примерами.
