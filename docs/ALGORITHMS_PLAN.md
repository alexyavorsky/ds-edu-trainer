# План справочника «Алгоритмы на Python» (поток С2)

Справочник главных алгоритмов и приёмов с анализом сложности: идея → код → разбор сложности → типичные ошибки.
Текст свой; ориентир по охвату и глубине — русскоязычные конспекты олимпиадной школы, но без олимпиадной
экзотики: только то, что встречается в задачах «Грокаем» и на собеседованиях. Графы — только BFS/DFS для
связности; геометрия, строки (кроме полиномиального хеша), потоки, деревья отрезков — вне плана.

Тема: `reference/algorithms/`, URL `/reference/algorithms/<статья>`, id `algorithms/<статья>`.
Python: код на стандартной библиотеке, совместим с Python 3.10+ и выполняется и в CPython, и в Pyodide.
Направление на сайте — «Python и алгоритмы» (вместе с ООП и «Грокаем»).

## Объём

**34 статьи** (Б 6 · С 22 · П 4 · итоговые 2), ≈ 220 примеров (6–8 на статью), статья — 80–200 строк MDX.
Ориентир по времени: как у справочника pandas на статью; вся тема — сопоставимо с половиной справочника NumPy.

Уровни: **Б** — базовый (`basic`), **С** — средний (`medium`), **П** — продвинутый (`advanced`).
«Грокаем» — задачи книги (id `ga-…`), к которым статья даёт теорию; они же попадут в блок «Задачи» статьи.

## Формат статьи

Файлы — как у NumPy/pandas: `reference/algorithms/<статья>.mdx` + `<статья>.py`, порядок — `topic.toml`.

Разделы: `## Коротко` → `## Идея` → `## Код` → `## Сложность` → (`## Доказательство` / свои) → `## Примеры` →
`## Подводные камни`. Последний раздел и есть «типичные ошибки» (название оставляем общим для всего
справочника — валидатор его требует). Нынешний валидатор это уже допускает: свои разделы ставятся после
«Коротко», «Синтаксис» и «Параметры» необязательны. В «Коде» — эталонная реализация через `<Example>`
(выполняется валидатором, на сайте — кнопка «Запустить»), в «Сложности» — вывод и подкрепление числами.

Frontmatter: `functions` — используемые функции стандартной библиотеки (`bisect.bisect_left`, `heapq.heappush`,
`collections.deque`) — для поиска; `docs` — ссылка на документацию Python там, где она есть (bisect, heapq,

(см. «Нужно от платформы»).

## Как подкрепляются утверждения о сложности

Главный способ — **счётчики операций с детерминированным выводом**, замеры — дополнение.

1. **Счётчики в setup статьи.** Сравнения считает обёртка ключа или класс-наследник `int` с
   `__lt__`, считающим вызовы; чтения — наследник `list` с `__getitem__` (как `_Tracked` в тестах задач);
   вызовы — счётчик в замыкании или `nonlocal`. Хелпер объявляется в `# %% setup` статьи, поэтому
   «Копировать» даёт самодостаточный код. Общий модуль хелперов не вводим.
2. **Таблица роста.** Пример печатает для n = 10, 100, 1 000, 10 000: число операций, отношение к n,
   к n·log₂n или к n² — отношение, которое стабилизируется, и есть ответ. Ширина колонок фиксирована (`f"{x:>8}"`),
   отношения округлены до 2 знаков. Вывод одинаков на любой машине, его сравнивает валидатор.
3. **Данные** — `random.Random(seed)`: последовательности `random()`, `randrange`, `shuffle`, `sample` у CPython
   стабильны между версиями и совпадают в Pyodide. Никаких `hash()` строк в выводе (PYTHONHASHSEED), порядок
   `set` не печатается — только `sorted(...)`.
4. **Замеры `[timing]`** — только там, где счётчик не показывает сути (цена операций Python, `sorted` на C
   против своей сортировки на Python, `deque` против `list.pop(0)`). Существующий механизм: вывод снимается
   один раз, хранится с машиной и датой, при проверке числа не сравниваются. Не больше ~15 замеров на тему,
   каждый укладывается в 2 с на CPython (в браузере медленнее в 3–5 раз — это видно на кнопке «Запустить»).
5. **Лимит размеров** — счётчики на n ≤ 10⁴ (O(n²) — n ≤ 2 000), чтобы пример выполнялся < 1 с в CPython и
   < 10 с (лимит примера) в Pyodide.

Ограничения Pyodide: рекурсия через `functools.cache` — глубина ≤ 40 в примерах (Safari), простая рекурсия ≤ 300;
пример, показывающий `RecursionError`, — флаг `[raises=RecursionError]` с глубиной 10⁴ (в браузере это может
быть аварийная остановка Pyodide — пометить в `reference/browser.json` как `unavailable`, если так).

## Нужно от платформы

1. **Тема без пакета.** `topic.toml`: `package` и `version` необязательны (схема в `src/content.config.ts`,

   статьи вместо версии библиотеки — «Python 3.10+».

   (для алгоритмов — пустой или только `import sys`). Сейчас общий prelude импортирует np/pd и matplotlib; в
   CPython это лишь медленнее, но `src/lib/python/packages.ts` всегда добавляет `numpy` (`new Set(['numpy',
   topicPackage])`) — для темы без пакета браузер не должен грузить NumPy.
3. **`docs` во frontmatter — необязательное** (для тем без пакета или вообще), подвал без «Документации», если поля нет.
4. **Поле `practice`** во frontmatter: список id задач (`ga-merge-sort`); валидатор справочника проверяет, что
   такие задачи есть; страница статьи показывает блок «Задачи» со ссылками и отметкой «решено» из localStorage.
5. **Навигация по направлениям.** Поле `direction` у `topic.toml`, `book.toml`, `course.toml`:
   `python` («Python и алгоритмы»: ООП, алгоритмы, «Грокаем»), `data` (NumPy, pandas), `git`, `english`.
   Главная и шапка группируют разделы по направлениям; порядок и подписи направлений — в `src/lib/labels.ts`.
6. **Пометка «бета»:** `beta = true` в `topic.toml` / `book.toml` / `course.toml` → значок «бета» на карточке и

   NumPy и алгоритмов смешаются на запросах вроде «сортировка») — желательно.
