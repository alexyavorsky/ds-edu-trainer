## Педагогика

- **Вход:** ноль по библиотеке, базовый Python (списки, словари, циклы, функции). Так написано на странице
  курса. Первый урок NumPy — «Python-минимум» с самопроверкой и ссылками, что повторить.
- **Курсы независимы: pandas проходится без курса NumPy.** Многие приходят именно за таблицами, а pandas
  прячет NumPy почти целиком: арифметика со столбцами, маски и агрегаты объясняются заново на Series, без
  массивов. Из самого NumPy курсу pandas нужно немного — `np.nan` (урок о пропусках), `np.where` и `np.select`
  (условные столбцы), тип `int64`/`float64` в `dtypes` — и это вводится там, где понадобилось. Требование
  «сначала NumPy» удлинило бы путь на 42 урока ради нескольких функций. Связь курсов задаёт поле `requires`
  в course.toml: у pandas оно пустое, поэтому проверка «понятие до объяснения» не засчитывает понятия курса
  NumPy — `np.nan` в уроке pandas обязан быть введён в `introduces` урока pandas. На странице курса pandas это
  написано в «Что нужно знать».
- **Одно понятие за раз:** короткое объяснение → демонстрация → упражнение. Длинной теории без практики нет.
- **Урок** — 10–20 минут, 3–6 упражнений (в мини-проекте — до 8).
- **Понятие не используется до объяснения.** В метаданных урока — список вводимых понятий (`introduces`);
  валидатор проверяет по коду каждого урока, что всё использованное введено в нём или раньше.
- **Повторение:** упражнения новых уроков опираются на понятия прошлых; валидатор печатает для каждого урока,
  какие старые понятия повторяются в его упражнениях.
- **Модуль** заканчивается мини-проектом на небольшом наборе данных (несколько шагов от загрузки до вывода),
  курс — итоговым проектом.
- **Типичные ошибки** объясняются там, где возникают, блоком «Типичная ошибка» и демонстрацией, которая эту
  ошибку показывает (список ниже в программах — «⚠»). Проверки упражнений ловят их и объясняют словами.
- **Язык:** русский, просто, без упрощений, которые потом придётся «разучивать». Термин при первом упоминании —
  с английским вариантом: «массив (array)». Текст свой, не пересказ документации.
- **Версии:** курс выполняется в Pyodide (NumPy 2.4.x, pandas 3.0.x), проверяется ещё и на версиях из
  `requirements-dev.txt` (NumPy 2.5.3, pandas 3.0.6). Используется только то, что есть в обеих. Возможность
  только новой версии упоминается текстом с пометкой, упражнений на ней нет.

### lesson.py

Ячейки в формате `# %%` (открывается в VS Code и Jupyter), по порядку урока — порядок совпадает с lesson.mdx
(проверяется). У упражнения тело ячейки — **эталон**, дальше разделы:

```python
# %% first                              ← демонстрация: <Demo id="first" />
import numpy as np
prices = np.array([120, 80, 45, 300])
prices

# %% list-float [raises=TypeError]      ← демонстрация, которая обязана упасть с этой ошибкой
# %% load-error [raises=FileNotFoundError, platform]   ← вывод в CPython и в браузере разный (Errno 2 и 44)
# %% x [warns]                          ← допустимы предупреждения (кроме Deprecation/Future)

# %% temps [exercise]                   ← упражнение: <Exercise id="temps">
temps = np.array([18, 21, 19, 25, 23, 17, 20])       # эталон
# ─── заготовка ───
temps = ...                             # `имя = ...` — переменные, которые ученик должен создать
# ─── проверка ───
def test_array():
    "temps — массив NumPy"               # строка документации — строка результата ✓ / ✗
    assert isinstance(temps, np.ndarray), f"temps — это {type(temps).__name__}, а нужен массив: …"
# ─── другое решение ───                 ← сколько угодно: обязаны проходить, и ячейки ниже — работать
temps = np.array(week)
# ─── ошибка ───                         ← типичные ошибки: проверка обязана поймать их понятным сообщением
temps = [18, 21, 19, 25, 23, 17, 20]

# %% division [quiz]                    ← необязательная проверка вопроса: значение = текст верного варианта
np.array([10, 20]) / 4
```

Упражнения переиспользуют устройство задач: заготовка / эталон / проверки `test_*` с docstring /
подсказки / альтернативные эталоны / типичные ошибки (как `mutants.toml`), тот же раннер
`runtime/runner.py` и те же статусы. Отличие одно: проверки работают с **состоянием урока**, а не с одной
функцией — тесты видят копию пространства имён урока (свои имена в урок не добавляют). Правила
из «Приёмов в тестах» (ARCHITECTURE.md) соблюдаются: значения сравниваются через `.tolist()`/`allclose`,
а не repr с dtype; байты — только отношениями; нет «решающих» вспомогательных функций. Проверка ловит
типичные ошибки заранее посчитанными неверными ответами и объясняет их («похоже, 32 прибавлено до
умножения…»). Если тест зависит от предыдущего условия (тип, длина), он сначала проверяет его сам —
иначе ученик увидел бы сырое исключение; валидатор это требует.

## Ячейки и состояние

Урок — ноутбук: **одно пространство имён Python на урок**. Устройство — `src/scripts/course/lesson.ts`,
выполнение — `runtime/lesson_exec.py` (тот же код в браузере и в CPython-валидаторе).

- **Сеанс.** Воркер с Python один на вкладку; урок держит в нём сеанс: пространство имён и рабочую папку
  с копиями файлов данных (`data/`). Импортов в сеанс никто не подставляет — первая ячейка урока пишет
  `import numpy as np` сама, как в Jupyter. `courses/prelude.py` задаёт только настройки отображения.
- **Номера выполнения** `[1]`, `[2]`… как в Jupyter: видно, что выполнено в этом сеансе; `[ ]` — нет.
  Над уроком — строка состояния: «Выполнено ячеек: 5 из 11», «Выполнить всё», «Перезапустить».
- **Запуск ячейки, когда выше что-то не выполнено — автоматически.** Невыполненные ячейки выше выполняются
  сами, по порядку, со строкой «Сначала выполняются ячейки выше: 2 из 5». Спрашивать не стал: ячейки урока
  короткие, выполняются за доли секунды, а забытые ячейки выше — самая частая беда новичка в Jupyter.
  Если ячейка выше падает, запуск останавливается и ячейка показывается.
- **Пропущенное упражнение не ломает следующие ячейки.** Упражнение выше считается готовым, если его
  проверка пройдена в этом сеансе. Иначе при автозапуске: если ученик что-то написал — его код проверяется;
  не прошёл (или не написан) — выполняется **эталонное решение**, а в упражнении появляется пометка «для ячеек
  ниже выполнено эталонное решение — ваш код не изменён». Код ученика в редакторе остаётся, эталон
  не показывается.
- **«Выполнить все выше»** (кнопка у каждой ячейки) и **«Выполнить всё»** выполняют ячейки заново по тем же
  правилам. **«Перезапустить»** — новое пространство имён и исходные файлы данных; идущий запуск
  останавливается. Если Python пришлось перезапустить (зависание, нехватка памяти), урок говорит, что
  состояние сброшено, и следующий запуск снова начнёт с ячеек выше.
- **Упражнение проверяется на текущем состоянии урока:** код ученика выполняется как ячейка (печать
  и значение видны), затем проверки. Переменная из заготовки не создана или всё ещё `...` — сообщение
  «замените многоточие своим кодом», а не падение тестов. Решено — отметка сохраняется.
- **Сохранение.** Изменённый код демонстраций не сохраняется (кнопка «Вернуть»). Код упражнений —
  в localStorage (`edu:code:v1:<урок>/<упражнение>` = `{code, starter, t}`, как у задач; обновилась заготовка —
  «оставить мой код / взять новую»). Прогресс — `edu:course:v1`: решённые упражнения, отметка урока, последний
  открытый урок курса («Продолжить»). У каждой записи время изменения `t` — для синхронизации (этап 4).
- **Урок пройден**, когда решены все упражнения; отметку можно поставить и снять вручную (явная отметка
  главнее). Уроки не блокируются — порядок рекомендованный.
- **Безопасность** как у задач: код выполняется только по нажатию; из адреса и ссылок — никогда.

## Проверка — `node scripts/validate_courses.ts [курс | id урока…] [--update] [--strict]`

- **Структура:** поля course.toml / module.toml / frontmatter, id с префиксом курса и уникальный, адрес урока
  уникален, 10–20 минут (5–30 — ошибка вне), 3–6 упражнений (в проекте до 8), порядок и виды ячеек в lesson.mdx
  и lesson.py совпадают, у вопроса ровно один верный вариант, у упражнения есть условие, эталон присваивает
  переменные заготовки; ссылки на справочник (frontmatter и `/reference/…` в тексте) и на уроки существуют.
  `--strict` (когда курс полный) — ещё и каждый модуль заканчивается мини-проектом.
- **Понятия по порядку:** в коде демонстраций, эталонов и заготовок собираются понятия (`np.x`, `pd.x`,
  `.метод`, `параметр=`). Каждое должно быть введено (`introduces`) в этом уроке или раньше; методы
  встроенных типов Python — известны с начала. Каждое введённое должно встречаться в коде урока.
  Ограничение: методы определяются по имени, без типа (`.sort` списка и массива — одно понятие).
- **Выполнение, в Pyodide (Node.js) и в CPython (`requirements-dev.txt`)**, каждый урок целиком, как ноутбук:
  с эталонами — всё работает, проверки проходят, вопросы с ячейкой `[quiz]` совпадают с верным вариантом;
  с заготовкой каждого упражнения (выше — эталоны) — проверка не проходит; с каждым «другим решением» —
  проходит, и все ячейки ниже работают; с каждой «ошибкой» — не проходит, причём сообщением assert, а не
  исключением. Deprecation/FutureWarning — ошибка; прочие предупреждения — только с `[warns]`.
- **Сохранённый вывод** — из Pyodide; `--update` перезаписывает output.json. Вывод CPython обязан совпадать,
  кроме ячеек `[platform]` (32-битный Python в браузере: `int32`, номера ошибок ОС).
- **Ноутбук:** экспорт с эталонами выполняется в CPython по ячейкам, как ядро Jupyter: ни одной ошибки,
  ячейки с намеренной ошибкой печатают её текст, каждая проверка — «Прошло N из N».

**В браузерах:** `node scripts/validate_browsers.ts` выполняет каждый урок с эталонами в Chromium, Firefox
и WebKit (production-сборка, тот же воркер, что у страницы): проверки проходят, вывод демонстраций совпадает
с сохранённым. Уроки добавляются в проверку сами, по мере написания.

CI: задание «Курсы» (ubuntu, Python 3.12 с `requirements-dev.txt`, Node 24, кэш пакетов Pyodide) и уроки
в задании «Python в браузерах». `--strict`
включится, когда курс будет полным (этапы 2–3).

## Синхронизация через Supabase (этап 4, отдельная ветка и PR)

Принцип: всё работает без входа; localStorage — основное хранилище, вход добавляет только синхронизацию.

- **Ключи:** `PUBLIC_SUPABASE_URL`, `PUBLIC_SUPABASE_ANON_KEY` в Vercel. Без них сайт такой же, как сейчас:
  кнопки входа нет, клиент Supabase не грузится. Service role key не нужен ни сайту, ни сборке и в репозиторий
  не попадает.
- **Вход:** основной — GitHub OAuth. Magic link по email — вариант, если настроен свой SMTP (встроенная отправка
  писем Supabase ограничена несколькими письмами в час); в README — как включить.
- **Загрузка:** `@supabase/supabase-js` — отдельным чанком, только если ключи заданы и человек нажал «Войти»
  или в браузере уже есть сессия.

Схема (`supabase/migrations/*.sql`):

```sql
create table public.progress (          -- «Решено» задач, пройденные уроки, решённые упражнения
  user_id    uuid not null default auth.uid() references auth.users on delete cascade,
  item       text not null check (item ~ '^(task|lesson|exercise):[a-z0-9/-]+$'),   -- task:ga-find-term
  done       boolean not null,
  updated_at timestamptz not null,
  primary key (user_id, item)
);
create table public.code (              -- код задач и упражнений
  user_id      uuid not null default auth.uid() references auth.users on delete cascade,
  item         text not null check (item ~ '^(task|exercise):[a-z0-9/-]+$'),
  code         text not null check (octet_length(code) <= 65536),
  starter_hash text not null,
  updated_at   timestamptz not null,
  primary key (user_id, item)
);
alter table public.progress enable row level security;
alter table public.code enable row level security;
create policy own_progress on public.progress for all to authenticated
  using (user_id = (select auth.uid())) with check (user_id = (select auth.uid()));
create policy own_code on public.code for all to authenticated
  using (user_id = (select auth.uid())) with check (user_id = (select auth.uid()));
```

- **Проверка политик:** SQL-тесты pgTAP в `supabase/tests/` (`supabase test db`): два пользователя через
  `request.jwt.claims`; каждый видит и меняет только свои строки, аноним — ничего; плюс скрипт с двумя
  настоящими тестовыми пользователями против проекта.
- **Слияние.** Отметки: объединение — отмечено хоть где-то → отмечено; снятие отметки — явное действие со
  временем, побеждает, только если оно новее отметки. Код: изменён только с одной стороны с прошлой
  синхронизации — берётся он; изменён с обеих — текущим становится более свежий, второй сохраняется как
  «другая версия» с плашкой в редакторе («версия с другого устройства от …: показать / взять / удалить») —
  без тихой потери. Первый вход — то же слияние всего локального с облаком.
- **Офлайн:** изменения помечаются как неотправленные и уходят при появлении сети (`online`) и при открытии
  страницы.
- **«Выйти»** — локальные данные остаются. **«Удалить мои данные»** — удаляет строки в Supabase (RLS пускает
  только к своим), локальные остаются.
- **Спящий проект.** Бесплатный проект Supabase засыпает после недели без активности: запросы падают или
  не отвечают. Сайт работает как без входа, у кнопки аккаунта — «Синхронизация недоступна, всё сохраняется
  в этом браузере», повтор позже.

## Вес

- Код курсов (скрипт урока, стили ячеек) грузится только на страницах уроков. Редактор, воркер и Python — только
  там, где есть что запускать (уроки, задачи, статьи справочника), и не на страницах-списках. Клиент Supabase
  (этап 4) — только когда настроен и используется.
- Страница урока (сборка, gzip): HTML 11–13 КБ (с сохранёнными таблицами), скрипт урока 6,5 КБ, редактор
  CodeMirror 125 КБ (общий с задачами), воркер 15 КБ.
- Python и пакеты — с jsDelivr, в фоне, когда браузер простаивает. Холодная загрузка (пустой кэш, Chromium,
  preview на Vercel, 01.10.2026), **передано по сети / распаковано**:

  | | Передано | Распаковано |
  | --- | --- | --- |
  | ядро Pyodide (wasm, stdlib, js) | 6,25 МБ | 13,5 МБ |
  | + NumPy | 2,93 МБ | 2,96 МБ |
  | + pandas и зависимости (dateutil, pytz, six) | 4,70 МБ | 4,94 МБ |
  | **урок NumPy** всего | 9,2 МБ | 16,5 МБ |
  | **урок pandas** всего | 13,9 МБ | 21,4 МБ |

  6,2 МБ «первой загрузки» из отчёта о Pyodide — это переданный (сжатый) размер ядра; 12 МБ в первом отчёте
  курсов — несжатые файлы. Колёса пакетов уже сжаты (zip), поэтому для них цифры почти равны.
- Холодный урок, «Выполнить всё» сразу после открытия страницы: NumPy — 3,3 с (11 ячеек), pandas — 5,2 с
  (13 ячеек, включая загрузку pandas и CSV). Повторный заход — из кэша браузера.
