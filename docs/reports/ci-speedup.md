## Как устроено

**План прогона** (`scripts/ci_changes.ts`, первое задание). Список файлов — `git diff` с merge-base
`origin/main` (или с веткой `base` при ручном запуске). Таблицы в одном файле:

- `GLOBAL` — общие части (package*.json, requirements-dev.txt, .github/workflows/, src/lib/python/,
  runtime/pyodide_driver.py, scripts/node-python.ts, scripts/pyodide-worker.ts, сам ci_changes.ts): всё и все id.
- `AREAS` — разделы `tasks`, `reference`, `courses`, `site`: `content` (файл задачи/статьи/урока — только этот id;
  файл книги, курса, модуля — весь раздел) и `shared` (раннер, валидатор раздела, courses/data/ — весь раздел).
- `JOBS` — задание → разделы, свои общие файлы (например, `validate_browsers.ts` для браузеров) и получает ли id.
- `IGNORED` — docs/, .claude/, README.md: ничего не запускают. **Любой другой незнакомый путь — как общая
  часть**: новый раздел без правил получит полный прогон, а не пропуск.

Вывод: `run_<задание>`, `ids_<задание>` (пусто — всё), матрицы JSON. Задания читают `needs.plan.outputs`.
Id передаются в валидаторы: курсы — `validate_courses.ts <id…>` (структура и порядок понятий — всегда по всем
курсам), Pyodide — `validate_pyodide.ts <id…>`, браузеры — `CHECK_ONLY`. Валидатор задач, файлы задач и
справочник — целиком (≤ 45 с, проверки главы и ссылок требуют всего раздела).

**Уровни.**

| | Ветка (push не в main, Run workflow `changed`) | Полный (push в main, ночь 01:23 UTC, Run workflow `full`) |
| --- | --- | --- |
| Что | затронутые задания, изменённые id | всё |
| Файлы задач | ubuntu 3.10 и 3.14 (границы поддержки), windows 3.12 (пути, кодировка консоли, `\r\n`) — macOS ведёт себя как Linux и стоит ×10 | 3 ОС × 3.10–3.14 |
| Браузеры | Chromium + WebKit: Chromium — большинство людей, WebKit — Safari с самым маленьким стеком (ловит то, что не ловят другие); Firefox ни разу не расходился с ними и проверяется в main и ночью | Chromium, Firefox, WebKit |
| Части браузера | до 12 id — одна, иначе 3 | 3 |
| Пробы глубины | только если проверяется всё (проверяют воркер и браузер, а не содержимое) | да |

**Браузеры по частям.** `validate_browsers.ts --shard k/n`: элемент i списка «задачи, затем уроки» — в часть
i mod n; внутри задания две вкладки параллельно (`--pages 2`: у раннера macOS 3 ядра; WebKit-часть ускорилась
с 235 до 108 с, Chromium — с 213 до 162 с; таймаутов от конкуренции за процессор не было). Пробы — отдельной
вкладкой в части 1 (раньше добавляли ~70 с к части 1). `--timings` → артефакт `browser-timings-*`.

**Устойчивость.** WebKit изредка теряет процесс страницы («page.waitForFunction: Target page closed» — так
упали прогон этой ветки 36755455906 и push-прогон PR #4 36772837925, повтор того же кода проходил; локально
не воспроизводится). Теперь страница сообщает о каждой начатой ячейке (`__step`) и каждой готовой задаче/уроке
(`__itemDone`); упала вкладка — один повтор для оставшихся id на новой вкладке (упал браузер — новый браузер),
в лог и `::warning`: «вкладка упала на уроке pd-plot, ячейка data, попытка 1 (…) — повтор, осталось: N».
Вторая неудача — ошибка с тем же местом. Проверено локально имитацией закрытия вкладки.
Второй вид сбоя — упал сам Python в воркере (прогон [36800879206](https://github.com/alexyavorsky/ds-edu-trainer/actions/runs/36800879206):
WebKit, урок pd-map-apply, ячейка map — «Pyodide already fatally failed»; локально и в остальных прогонах урок
проходит). Статусы `crash`, `load-error`, «fatally failed», «Out of bounds memory» — это не провал проверки, а
падение среды: такая задача или урок выполняется ещё раз отдельной вкладкой, в лог — `::warning` с местом.
Провал тестов, расхождение вывода и таймауты не повторяются.

**Ворота `ci-ok`.** `needs` — все задания, `if: always()`; зелёное, если план прошёл, а каждое задание `success`
или `skipped`. Делать обязательной проверкой только его (защиты ветки main сейчас нет).

**pull_request не запускает workflow.** Push-прогон ветки и так виден в PR; второй прогон того же коммита
удваивал бы минуты macOS и давал два `ci-ok` (пропущенное задание считается успешным для обязательной
проверки — это ослабило бы ворота). Минус: PR из форков без CI.

**concurrency.** `ci-<ref>` с `cancel-in-progress`: новый push в ветку отменяет её незаконченный прогон.
В main группа включает `run_id` — прогон слияния не отменяется и не ждёт следующего.

**Кэши.** pip (`requirements-dev.txt`), npm (`package-lock.json`), браузеры Playwright
(`~/Library/Caches/ms-playwright`, ключ: ОС, архитектура, версия playwright, браузер — установка 30 с → 2–12 с),
пакеты Pyodide для Node.js (`.pyodide-cache`). Пакеты Pyodide в браузерах берёт HTTP-кэш браузера внутри
вкладки (каждая скачивает один раз); перехват запросов воркера Playwright'ом ради нескольких секунд не делал.

## Как добавить задание для нового раздела (для П2)

1. **Правила путей** — `scripts/ci_changes.ts`:
   - новый раздел в `AREAS`: `content` — папки содержимого, `shared` — его валидатор и общие файлы,
     `item(file)` — id по пути (или без `item`: любое изменение — весь раздел);
   - новое задание в `JOBS`: `{ areas: ['<раздел>'], shared: [...], ids: true|false }`;
   - если раздел должен попадать в браузеры или сайт — добавить его в `areas` задания `browsers` / `site`.
   Проверить: `node scripts/ci_changes.ts --files <путь>` — таблица покажет, что запустится.
2. **Workflow** — `.github/workflows/tasks.yml`:
   - в `plan.outputs` — `run_<задание>` (и `ids_<задание>`, если `ids: true`);
   - задание с `needs: plan` и `if: needs.plan.outputs.run_<задание> == 'true'`; id — из
     `needs.plan.outputs.ids_<задание>` (пусто — всё);
   - добавить его в `needs` задания `ci-ok` — иначе его падение не остановит ворота.
3. Примеры из планов:
   - **Справочник ООП/алгоритмов без пакетов** (ALGORITHMS_PLAN п. 7, OOP_PLAN П1/П4) — это раздел `reference`
     с новой темой: ничего добавлять не нужно (`reference/<тема>/…` уже даёт id «тема/статья»); если выводу нужен
     Python 3.14 — поменять версию в заданиях «Справочник» и «Курсы».
   - **Задачи NumPy/pandas** (TASKS_PLAN п. 7) — раздел `tasks` уже покрывает `challenges/`; в «Валидации задач» и
     «Файлах задач» добавить `pip install -r requirements-dev.txt` (кэш pip уже есть в других заданиях),
     для браузеров — при желании только Chromium для задач тем: условие в `ci_changes.ts` (разные `ids` по
     браузеру) или `--only` в отдельном шаге.
   - **Git** (GIT_PLAN п. 5) — `AREAS.git = { content: ['reference/git/'], shared: ['scripts/validate_git.py'] }`
     — путь `reference/git/` надо убрать из `reference` (условие в `articleId` или отдельный префикс раньше
     в списке); `JOBS.git = { areas: ['git'] }`; задание на ubuntu: `actions/cache` для `~/git` по версии из
     `topic.toml`, сборка git при промахе, `validate_git.py --strict --check-determinism`.
   - **Английский** (ENGLISH_PLAN п. 15–16) — `AREAS.english = { content: ['reference/english/', 'courses/english/'],
     shared: ['scripts/validate_english.ts', 'src/lib/english/'] }`, `JOBS.english = { areas: ['english'] }`,
     задание Node без Python и Pyodide; если уроки английского проверяются в браузерах — `english` в `areas`
     задания `browsers` и их id в `loadLessons` скрипта браузеров.
