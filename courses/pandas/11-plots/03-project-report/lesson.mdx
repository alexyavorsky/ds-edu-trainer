Владелец «Кофейной лавки» хочет получать один и тот же отчёт каждый месяц — по свежей выгрузке. Значит,
анализ должен быть записан так, чтобы его можно было запустить снова, ничего не меняя, и чтобы через полгода
было понятно, что делает каждая строка. Соберём такой отчёт из цепочек. Новых методов в проекте нет.

## Шаг 1. Подготовка — одной функцией

Выручка строки и номер месяца нужны почти в каждом расчёте. Оформим их добавление функцией: тогда любая
цепочка начнётся одинаково — `.pipe(prepare)`.

<Exercise id="prepare" title="Функция prepare">
Допишите функцию `prepare(table)`: она возвращает таблицу с двумя новыми столбцами — `revenue` (цена ×
количество) и `month` (номер месяца из `date`). Исходную таблицу функция менять не должна. Затем сохраните
в `orders` результат её применения к `raw`.

<Hint>`return table.assign(revenue=lambda d: d["price"] * d["quantity"], month=lambda d: d["date"].dt.month)` — в одном `assign` можно задать несколько столбцов.</Hint>
<Hint>`orders = raw.pipe(prepare)`.</Hint>
</Exercise>

## Шаг 2. Выручка по месяцам

<Exercise id="monthly" title="Первая цепочка">
Цепочкой от `raw` получите `monthly` — выручку по месяцам: подготовка через `pipe`, группировка по `month`,
сумма `revenue`. В `best_month` сохраните номер месяца с наибольшей выручкой.

<Hint>`.pipe(prepare)`, затем `.groupby("month")["revenue"]` и `.sum()` — каждый шаг с новой строки.</Hint>
</Exercise>

## Шаг 3. Каналы и доля сайта

В цепочке можно не только сворачивать данные, но и добавлять столбцы к уже свёрнутой таблице — `assign`
с `lambda` получит сводную таблицу «на этом шаге».

<Exercise id="channels" title="Сводная с вычисляемыми столбцами">
Цепочкой от `raw` получите `channels`: сводная таблица выручки (месяцы в строках, каналы в столбцах), к которой
добавлены столбцы `total` — сумма трёх каналов — и `site_share` — доля сайта в `total`, три знака.

<Hint>`.pivot_table(values="revenue", index="month", columns="channel", aggfunc="sum")`.</Hint>
<Hint>`.assign(total=lambda d: d["сайт"] + d["приложение"] + d["маркетплейс"])`, затем ещё один `assign` для `site_share`.</Hint>
</Exercise>

<Demo id="channels-view" title="Первые месяцы" />

Два `assign` подряд, а не один — потому что второму нужен столбец `total`, созданный первым.

## Шаг 4. Свой шаг с параметрами

«Лучшие товары категории» пригодятся для любой категории и любого числа товаров — значит, это функция
с параметрами. Внутри неё — тоже цепочка.

<Exercise id="top" title="Лучшие товары категории">
Допишите функцию `top_products(table, category, n)`: она возвращает таблицу из `n` товаров категории
`category` с наибольшей выручкой — столбцы `product` и `revenue`, индекс с нуля. Затем получите `top_tea` —
два лучших чая — цепочкой с двумя `pipe`.

<Hint>В `query` параметр функции — как любая переменная: `.query("category == @category")`.</Hint>
<Hint>Дальше `.groupby("product", as_index=False)["revenue"]`, `.sum()`, `.nlargest(n, "revenue")`, `.reset_index(drop=True)`.</Hint>
<Hint>`raw.pipe(prepare).pipe(top_products, "Чай", 2)`.</Hint>
</Exercise>

## Весь путь целиком

Вот как выглядит отчёт «от файла до графика» одной цепочкой. Здесь собрано многое из курса: чтение
с датами, свой шаг, фильтр, индекс из дат, пересчёт в недели, окно и график.

<Demo id="whole" title="От CSV до графика" />

Прочитайте её сверху вниз: загрузить → подготовить → оставить кофе → даты в индекс → сложить по неделям →
убрать неполные недели → сгладить окном в четыре недели → нарисовать. Каждая строка — один шаг, и каждый можно
закомментировать, чтобы посмотреть на промежуточный результат.

## Выводы

- Сайт даёт от 39 до 66 % выручки в зависимости от месяца; самая высокая его доля — в октябре.
- Лучшие чаи — улун и зелёный; лучшие сорта кофе — в пачках по 250 г и килограммовая «Бразилия».
- Кофе продаётся ровно весь год с провалом в июле — августе.

И главное — про сам код. Функцию `prepare` мы написали один раз и использовали на каждом шаге. Если владелец попросит
считать выручку со скидкой, правка понадобится в одном месте. Это и есть «хороший код» для аналитика:
не самый короткий и не самый хитрый, а такой, который легко прочитать, проверить и запустить снова.
