## Коротко

- В pandas 3 **Copy-on-Write** включён всегда: любая выборка, столбец или результат метода ведёт себя как **отдельная копия**.
- Изменение выборки (`low = df[mask]; low["x"] = 0`) не меняет исходную таблицу, и предупреждений об этом больше нет.
- **Цепочечное присваивание** `df["col"][0] = 1` никогда не меняет `df` — выдаётся `ChainedAssignmentError`. Изменять нужно одной операцией: `df.loc[0, "col"] = 1`.
- Копирование ленивое: данные копируются только в момент изменения, поэтому `reset_index`, `rename` и подобные методы стали дешёвыми.
- `.copy()` «на всякий случай» после фильтра больше не нужен.

## Было и стало

| Код | pandas 2.x | pandas 3 |
| --- | --- | --- |
| `sub = df[mask]; sub["x"] = 0` | `SettingWithCopyWarning`, результат неочевиден | меняется только `sub` |
| `s = df["a"]; s[0] = 9` | иногда менял `df` | меняется только `s` |
| `df["a"][0] = 9` | иногда работал | не работает, `ChainedAssignmentError` |
| `df.loc[0, "a"] = 9` | работает | работает |
| `df["a"].to_numpy()` | изменяемый массив | массив только для чтения |
