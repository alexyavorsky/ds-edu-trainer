Атрибут, который можно свободно менять снаружи, легко испортить: подарочной карте записать отрицательный
баланс, заказу — несуществующий статус. Объект не может защитить себя, если любой код пишет в его атрибуты
что угодно. Решение называется **инкапсуляция** (encapsulation): объект прячет своё внутреннее состояние и
даёт менять его только через свои методы — а методы проверяют, что изменение допустимо.

## Публичный интерфейс и внутренние атрибуты

Методы и атрибуты, которыми пользуются снаружи, образуют **публичный интерфейс** класса (public API).
Всё остальное — внутреннее устройство. В Python нет закрытых атрибутов, как `private` в Java или C++, — есть
соглашение: имя, которое начинается с подчёркивания, — **внутренний атрибут**. Его можно прочитать и
изменить, но код снаружи так не делает: это детали, которые автор класса вправе поменять.

<Demo id="gift-card" title="Баланс прячется за методами" />

Снаружи с картой работают только через `balance()` и `pay()`. Метод `pay` проверяет, хватает ли денег, —
и баланс не уйдёт в минус, пока никто не лезет в `_balance` напрямую.

Допишите класс `GiftCard`: у него уже есть `balance()` и `pay(amount)`. Добавьте метод `top_up(amount)`:

## Два подчёркивания: искажение имён

Имя с **двумя** подчёркиваниями в начале, `__code`, Python внутри класса тихо переименовывает:
к нему приписывается имя класса — `_Safe__code`. Это называется **искажение имён** (name mangling):

<Demo id="mangling" title="Где на самом деле лежит __code" />

<Demo id="mangling-error" title="Снаружи имени __code нет" />

Снаружи `safe.__code` не найдётся, но `safe._Safe__code` прочитать можно — это тоже не защита. Искажение имён нужно
для другого: чтобы атрибут класса случайно не перезаписал его подкласс с таким же именем атрибута (о
подклассах — в модуле 5). Поэтому для внутренних атрибутов обычно хватает одного подчёркивания, а два
пишут, когда важно не столкнуться с именами в подклассах.

<Exercise id="terminal" title="ПИН-код терминала">
Объявите класс `Terminal`: `Terminal("1234")` хранит ПИН-код в атрибуте `__pin` — с двумя подчёркиваниями.
Метод `check(pin)` возвращает `True`, если переданный код совпадает с сохранённым, иначе `False`.

<Hint>В `__init__`: `self.__pin = pin`; внутри класса имя пишется так же — `self.__pin`.</Hint>
</Exercise>

<Quiz id="private-quiz">
Что будет, если снаружи класса выполнить `card._balance = 1_000_000`?

- [x] сработает: Python не запрещает менять атрибуты с подчёркиванием
- [ ] `AttributeError`: атрибут с подчёркиванием только для чтения
- [ ] `PermissionError`: доступ к внутреннему атрибуту закрыт

<Explain>Подчёркивание — соглашение между программистами, а не замок. Python выполнит присваивание, а все проверки в методах `pay` и `top_up` окажутся бесполезны. Поэтому внутренние атрибуты снаружи не трогают.</Explain>
</Quiz>

Итак: публичный интерфейс — имена без подчёркивания, внутреннее — с `_`. Методы с проверками стерегут
состояние. Но у методов есть неудобство: баланс читается вызовом `balance()`, а хотелось бы — как атрибут,
`card.balance`. Как сделать атрибут, который нельзя испортить, — в следующем уроке.
