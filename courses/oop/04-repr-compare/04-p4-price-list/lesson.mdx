Поставщик прислал «Кофейной лавке» два прайса — утренний и вечерний. Многие позиции в них повторяются,
а у некоторых за день изменилась цена. Нужно свести прайсы в один без повторов, отсортировать его и найти
товары с новой ценой. Всё это делается магическими методами модуля: `__repr__`, `__eq__`, `__hash__` и `__lt__`.

## Шаг 1. Товар

<Exercise id="product" title="Товар для прайса">
Допишите класс `Product`:

- `__repr__` возвращает `Product('Латте', 220)`;
- товары равны, если совпадают и название, и цена; сравнение с чужим типом — `NotImplemented`;
- `__hash__` согласован с `__eq__`, чтобы товары можно было класть в `set`.

<Hint>Хеш из тех же атрибутов, что сравнивает `__eq__`: `hash((self.name, self.price))`.</Hint>
</Exercise>

## Шаг 2. Порядок в прайсе

<Exercise id="order" title="Сначала дешёвые">
Добавьте в класс (скопируйте его из шага 1 целиком) метод `__lt__`: товар «меньше», если он дешевле, а при
равной цене — если его название раньше по алфавиту. Сравнение с чужим типом — `NotImplemented`.

<Hint>Кортежи сравниваются по порядку: `(self.price, self.name) < (other.price, other.name)`.</Hint>
</Exercise>

## Шаг 3. Два прайса в один

<Exercise id="merge" title="Без повторов">
По спискам пар `morning` и `evening` создайте товары и сохраните в `all_items` общий список — сначала утренние,
потом вечерние. В `unique` сохраните множество (`set`) товаров без повторов, а в `n_dupes` — сколько позиций
оказались повторами.

<Hint>`[Product(n, p) for n, p in morning + evening]` — оба списка подряд.</Hint>
<Hint>Повторов столько, на сколько `all_items` длиннее `unique`.</Hint>
</Exercise>

## Шаг 4. Прайс по цене

<Exercise id="price-list" title="Сортировка">
Сохраните в `price_list` список товаров из `unique`, отсортированный по естественному порядку товаров
(шаг 2), а в `cheapest3` — названия трёх самых дешёвых.

<Hint>`sorted(unique)` — `set` сортируется так же, как список, результат — список.</Hint>
</Exercise>

## Шаг 5. Что подорожало

Один и тот же товар с разными ценами — это два **разных** товара для `__eq__`: в `unique` остались оба.

<Exercise id="changed" title="Товары с новой ценой">
Сохраните в `alphabet` названия всех товаров `unique` по алфавиту (повторяющиеся названия — подряд), а в
`changed` — список названий, которые встречаются в `unique` больше одного раза, то есть товаров, у которых
за день изменилась цена. Каждое название — один раз, по алфавиту.

<Hint>`alphabet = sorted(p.name for p in unique)` — порядок по названию задаётся снаружи, `__lt__` для этого не нужен.</Hint>
<Hint>Посчитайте названия словарём-счётчиком и возьмите те, у которых счётчик больше 1.</Hint>
</Exercise>

<After id="*">
Из десяти позиций двух прайсов три оказались повторами, в сводном прайсе семь товаров. Цена за день
изменилась только у латте: утром 220 ₽, вечером 240 ₽. Заметьте, как удобно смотреть на такие списки, когда
у товара есть `__repr__`: `print(price_list)` сразу показывает и названия, и цены.
</After>

Два порядка в одном проекте — хороший пример правила из урока о сортировке: естественный порядок прайса
(по цене) задан в классе, а порядок по алфавиту — снаружи, ключом. В следующем модуле появятся иерархии
классов: разные виды скидок, которые касса применяет одинаково.
