До сих пор экземпляры своих классов мы не печатали — только их атрибуты. И не зря: без подготовки Python
печатает экземпляр так:

```text
>>> latte = Product("Латте", 220)
>>> latte
<__main__.Product object at 0x10a3f2b50>
```

Имя класса и адрес объекта в памяти — для отладки почти бесполезно, а адрес к тому же меняется при каждом
запуске. Научим класс выглядеть понятно.

## Магические методы

`__init__` — не единственный метод с двумя подчёркиваниями. Таких методов десятки, и все они устроены
одинаково: **Python вызывает их сам**, когда с объектом делают что-то встроенное. `len(x)` вызывает
`x.__len__()`, `print(x)` — `x.__str__()`, а `__init__` — создание экземпляра. Их называют **магическими
методами** (special methods; их ещё называют dunder — от double underscore). Объявите такой метод в своём
классе — и встроенная операция заработает с вашими объектами.

## `__repr__`: представление для отладки

Метод `__repr__` возвращает **строковое представление** (representation) объекта для программиста. Его
показывает Jupyter для значения последней строки ячейки, его используют списки и словари, когда печатают
свои элементы, и его возвращает встроенная функция `repr()`. Хорошее представление однозначно и, по
возможности, похоже на код, который создаёт такой же объект:

<Demo id="repr" title="Product с __repr__" />

Обратите внимание на `!r` в f-строке: `{self.name!r}` вставляет не саму строку, а её `repr` — с кавычками.
Без них `Product(Латте, 220)` уже не похоже на код.

<Exercise id="drink-repr" title="Представление напитка">
Допишите класс `Drink`: метод `__repr__` возвращает строку вида `Drink('Латте', 220)` — имя класса, название
в кавычках и цену.

<Hint>`return f"Drink({self.name!r}, {self.price})"`.</Hint>
</Exercise>

<Exercise id="order-str" title="Заказ для журнала и для кассы">
Допишите класс `Order`: `__repr__` возвращает `Order(17, 640)` — номер и сумму, а `__str__` — текст для

<Quiz id="list-quiz">
У класса `Order` из упражнения есть и `__str__`, и `__repr__`. Что напечатает `print([Order(17, 640)])`?

- [ ] `[Заказ №17 на 640 ₽]`
- [x] `[Order(17, 640)]`
- [ ] `[<__main__.Order object at 0x…>]`

<Explain>`print` вызывает `__str__` у самого списка, а список собирает свой текст из `repr` элементов. Поэтому внутри списка, словаря и кортежа всегда видно представление для отладки.</Explain>
</Quiz>

## repr и str в f-строках

В f-строке `{x}` даёт `str(x)`, а `{x!r}` — `repr(x)`. Первое — для сообщений людям, второе — для журналов
и сообщений об ошибках, где важно точно видеть значение:

<Exercise id="log" title="Два сообщения">
Для заказа `order` составьте две строки: `message` — `"Готов: Заказ №17 на 640 ₽"` для экрана выдачи (через
`__str__`) и `log` — `"создан Order(17, 640)"` для журнала (через `__repr__`). Используйте f-строки с самим
объектом, без обращения к его атрибутам.

<Hint>`f"Готов: {order}"` и `f"создан {order!r}"`.</Hint>
</Exercise>

Правило на будущее: **у каждого своего класса должен быть `__repr__`** — отладка без него мучительна.
`__str__` — когда объекту нужен отдельный «человеческий» вид.
