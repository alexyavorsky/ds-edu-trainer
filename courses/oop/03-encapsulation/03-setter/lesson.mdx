Свойство только для чтения не даёт изменить атрибут через публичный интерфейс. Но цену товара менять нужно — просто не на любое
значение: отрицательная цена — ошибка в программе, и лучше узнать о ней сразу. Для этого у свойства бывает
вторая половина — **сеттер** (setter): метод, который вызывается при *записи* в свойство.

## Сеттер

Сеттер объявляется вторым методом с тем же именем и декоратором `@имя.setter`. Он получает новое значение,
проверяет его и записывает во внутренний атрибут:

## raise: сообщить об ошибке

Что делать, если значение неверное? Молча проигнорировать — плохо: программа продолжит работать с неверными
данными, и ошибка всплывёт далеко отсюда. Правильно — **выбросить исключение** (raise) — так же, как это
делает Python, когда вы пишете `int("сто")`:

<Demo id="raise" title="Неверный объём — ValueError" />

`raise ValueError("…")` сразу прерывает метод: строки ниже не выполняются, атрибут не меняется, а вызвавший
код получает исключение. `ValueError` — встроенное исключение для «значение подходящего типа, но
недопустимое». Сообщение пишут так, чтобы было понятно, что исправить.

Вызывающий код может перехватить исключение в `try/except` и решить, что делать дальше. Запись
`except ValueError as error` даёт перехваченному исключению имя: `str(error)` — его сообщение.

<Exercise id="price" title="Цена с проверкой">
Допишите класс `Product`: свойство `price` возвращает `_price`, а сеттер записывает новую цену, если она больше
нуля, иначе выбрасывает `ValueError` с сообщением `"цена должна быть больше нуля"`. Неудачная попытка не меняет
старую цену.

<Hint>Сеттер: `@price.setter`, затем `def price(self, value):`. Внутри — `if value <= 0: raise ValueError(...)` и после проверки `self._price = value`.</Hint>
</Exercise>

<Mistake title="рекурсия в сеттере">
Внутри сеттера легко написать `self.price = value` вместо `self._price = value`:

```python
@price.setter
def price(self, value):
    if value <= 0:
        raise ValueError("цена должна быть больше нуля")
    self.price = value  # ошибка: это снова вызов сеттера
```

Запись в `self.price` — это снова вызов сеттера, который снова пишет в `self.price`… Метод вызывает сам себя
без конца, пока Python не остановит его ошибкой `RecursionError: maximum recursion depth exceeded` (в браузере
вместо неё Python может просто перезапуститься — стек там меньше). Внутри геттера и сеттера всегда работайте
с внутренним атрибутом `_price`.
</Mistake>

## Проверка при создании

Сеттер срабатывает при любой записи в свойство — и в `__init__` тоже. Если в `__init__` написать
`self.volume = volume` (без подчёркивания), неверный экземпляр просто не создастся:

<Quiz id="init-quiz">
В `__init__` класса с сеттером цены написано `self._price = price`. Что будет при `Product("Чай", -5)`?

- [x] экземпляр создастся с ценой -5
- [ ] `ValueError`: сеттер проверит цену
- [ ] `AttributeError`: у свойства нет такого атрибута

<Explain>Запись в `_price` — это запись в обычный атрибут, сеттер `price` при этом не вызывается. Чтобы проверка работала и при создании, `__init__` должен писать в свойство: `self.price = price`.</Explain>
</Quiz>

<Exercise id="review" title="Оценка в отзыве">
Объявите класс `Review`: `Review("Анна", 5)` хранит имя автора в атрибуте `author` и оценку в свойстве `stars`.
Оценка — число от 1 до 5; число вне этого диапазона — и при создании, и при изменении — выбрасывает
`ValueError`.

<Hint>В `__init__`: `self.stars = stars` — запись через свойство, чтобы сработала проверка.</Hint>
<Hint>В сеттере проверьте обе границы — и меньше 1, и больше 5 — и только потом записывайте `_stars`.</Hint>
</Exercise>

## Неверные данные на входе

Проверки в сеттерах особенно полезны, когда данные приходят извне — из файла или формы. Объект сам не даст
создать себя с ошибкой, а программа перехватит исключение и пропустит плохую строку.
