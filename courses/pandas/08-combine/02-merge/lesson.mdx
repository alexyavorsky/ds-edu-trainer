До сих пор мы работали с таблицей `shop_orders.csv`, где в каждой строке уже записаны и город покупателя,
и название товара, и цена. Настоящие базы данных устроены иначе: сведения хранятся **в разных таблицах**
без повторов. Название и цена товара записаны один раз — в справочнике товаров, а в заказах стоит только
его код.

<Demo id="tables" title="Заказы и справочник товаров" />

В заказах нет цены — есть `product_id`. В справочнике нет продаж — есть `product_id`, цена и себестоимость.
Чтобы посчитать выручку, нужно к каждой строке заказа **подставить** строку справочника с тем же кодом.
Общий столбец, по которому сопоставляются строки, называют **ключом**.

## merge на маленьком примере

Две таблицы с общим столбцом `id`:

<Demo id="toy" title="Соединение по id" />

Метод `merge` взял каждую строку левой таблицы, нашёл в правой строку с тем же `id` и склеил их в одну.
В результате остались только ключи 2 и 3 — те, что есть **в обеих** таблицах. Ани (id 1) в правой таблице нет,
Омска (id 4) нет в левой — и обе строки пропали. Такое соединение называется **внутренним** (`inner`), и оно
используется по умолчанию.

Параметр `how` («как») меняет правило. `how="left"` сохраняет **все строки левой** таблицы; где пары
не нашлось, ставит пропуск:

<Demo id="toy-left" title="Все строки левой таблицы" />

Остальные варианты — `"right"` (все строки правой) и `"outer"` (все строки обеих):

<Demo id="toy-outer" title="Все строки обеих таблиц" />

Все четыре вида на одной схеме:

<MergeDiagram />

<Quiz id="how-quiz">
Сколько строк будет в `left.merge(right, on="id", how="right")`?

- [ ] `2`
- [x] `3`
- [ ] `4`

<Explain>`how="right"` сохраняет все строки правой таблицы — их три: id 2, 3 и 4. У строки с id 4 в столбце `name` будет пропуск. Две строки дал бы `inner`, четыре — `outer`.</Explain>
</Quiz>

## Заказы и товары

<Demo id="real" title="К каждой строке заказа — данные товара" />

В `orders` один и тот же товар встречается в сотнях строк, в `products` — один раз. `merge` подставил
строку справочника **к каждой** строке заказа с этим кодом. Такое соединение называют «многие к одному» —
самый частый случай.

Число строк не изменилось: было 2448 — и стало 2448. Это первое, что проверяют после соединения.

## Строки без пары

Теперь покупатели. В справочнике `customers.csv` — 240 клиентов. Посчитаем, сколько заказов сделал каждый:

<Demo id="customers" title="Справочник клиентов и число заказов" />

Клиентов 240, а в таблице с числом заказов только 213 строк: остальные ничего не покупали в 2025 году,
и в заказах их просто нет. Что будет при соединении?

<Demo id="inner-loss" title="inner и left" />

Внутреннее соединение молча выбросило 27 клиентов. Ошибки нет, таблица выглядит нормально — и «среднее число
заказов на клиента», посчитанное по ней, окажется завышенным.

<Mistake title="inner теряет строки без пары">
Соединение по умолчанию оставляет только совпавшие ключи. Если слева — полный список (клиенты, товары, даты)
и ни одна его строка не должна пропасть, пишите `how="left"` и сравнивайте число строк до и после.
</Mistake>

С `how="left"` клиенты без заказов остаются, а в столбце `orders` у них пропуск:

Из-за пропусков столбец стал дробным. Здесь пропуск значит «ноль заказов» — его можно и нужно заполнить.

## Брать только нужное

Соединять можно и несколько раз подряд. Добавим к заказам с товарами сегмент покупателя. Из справочника
клиентов возьмём только два столбца — ключ и то, что нужно:

<Demo id="narrow" title="Третья таблица — только ключ и сегмент" />

Так результат не засоряется лишними столбцами. Есть и вторая причина: в обеих таблицах есть столбец `name`
(название товара и имя клиента) — что происходит при совпадении названий, разберём в следующем уроке.

<Exercise id="segments" title="Сегменты покупателей">
По таблице `with_segment` соберите `segment_stats` — таблицу по сегментам (сегмент в индексе): `revenue` —
выручка, `buyers` — число разных покупателей. Добавьте столбец `per_buyer` — выручка на одного покупателя,
округлённая до рублей. В `best_segment` сохраните сегмент с наибольшим `per_buyer`.

<Hint>`with_segment.groupby("segment").agg(revenue=("revenue", "sum"), buyers=("customer_id", "nunique"))`.</Hint>
<Hint>`(segment_stats["revenue"] / segment_stats["buyers"]).round()` и `idxmax()`.</Hint>
</Exercise>

Оптовых покупателей всего 25, но каждый приносит 30 тысяч рублей в год — вдвое больше остальных.

## Итоги

- `левая.merge(правая, on="ключ")` — к каждой строке левой таблицы подставить строку правой с тем же ключом.
- `how="inner"` (по умолчанию) — только совпавшие ключи; `how="left"` — все строки левой, без пары — `NaN`.
- После соединения сравните число строк с исходным.
- Берите из правой таблицы только нужные столбцы: `правая[["ключ", "столбец"]]`.
