Продажи по дням, температура по дням, курс валюты по дням — всё это **временные ряды**: значения, у каждого
из которых есть момент времени. Главный вопрос к таким данным — «что было в таком-то периоде». Отвечать на него
проще всего, когда даты стоят в индексе.

## Дни, которых нет

Соберём ряд выручки магазина по дням:

<Demo id="daily" title="Выручка по дням" />

Дней в году 365, а в ряду — 358. В семь дней покупок не было, и в таблице продаж этих дат просто нет.
Группировка не может создать строку для даты, которая не встретилась:

<Demo id="missing-day" title="2 июля продаж не было" />

Для временного ряда это проблема. Среднее по 358 дням завышает «выручку в день»; неделя из шести дней
сравнивается с неделей из семи; на графике пропавший день незаметен. Нужен ряд с **полным календарём**.

Функция `pd.date_range` создаёт набор дат от начала до конца — по дню на каждую:

<Demo id="date-range" title="Пять дней подряд" />

А `reindex` из прошлого модуля приводит ряд к этому набору: для дат, которых не было, ставит указанное
значение.

## Индекс должен быть отсортирован

Срезы по датам рассчитаны на то, что даты идут по порядку. Если строки перемешаны, срез не сработает:

<Demo id="unsorted" title="Срез по неотсортированным датам" />

<Mistake title="partial slicing on non-monotonic DatetimeIndexes">
«Non-monotonic» значит «не по порядку». После сортировки по другому столбцу или склейки нескольких файлов
даты перемешиваются. Верните порядок — `sort_index()` — и срезы заработают.
</Mistake>

## Итоги

- `set_index("date")` — даты в индексе; дальше `loc` понимает даты строкой.
- `loc["2025-03"]` — весь месяц, `loc["2025"]` — весь год, `loc["2025-06":"2025-08"]` — период, обе границы входят.
- У индекса из дат есть `index.month`, `index.dayofweek` и другие части — без `.dt`.
- В данных может не быть строк для «пустых» дней: `pd.date_range` и `reindex` восстанавливают календарь.
- Срезы по датам требуют отсортированного индекса.
