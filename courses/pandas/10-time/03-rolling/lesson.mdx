Дневная выручка прыгает: сегодня 9 тысяч, завтра 18, послезавтра 4. За этими скачками трудно разглядеть,
растут продажи или падают. `resample` из прошлого урока укрупняет данные — но вместе с шумом теряет и
подробности: из 365 точек остаётся 12. Есть способ сгладить ряд, сохранив точку на каждый день.

## Скользящее окно

Идея: для каждого дня взять не одно его значение, а итог по нескольким последним дням. Метод `rolling(n)`
«прикладывает» к ряду окно из `n` значений и двигает его на шаг за шагом.

<Demo id="toy" title="Окно из трёх значений: сумма и среднее" />

Третье значение суммы — 1 + 2 + 3 = 6, четвёртое — 2 + 3 + 4 = 9: окно сдвинулось на одно значение. Первые
два результата — `nan`: окно из трёх значений там ещё не набралось.

Теперь выручка магазина по дням — ряд с полным календарём из прошлых уроков:

<Demo id="sales" title="Первые восемь дней года" />

<Demo id="week-mean" title="Среднее за семь дней" />

Каждое число — средняя дневная выручка за семь дней, **заканчивая этим днём**. Это и есть **скользящее
среднее**. Окно в семь дней выбрано не случайно: в него всегда попадает ровно по одному понедельнику,
вторнику и так далее, и недельный ритм (в выходные покупают больше) не мешает.

<Quiz id="roll-quiz">
Что выведет `print(pd.Series([10, 20, 30, 40]).rolling(2).mean().tolist()[-1])`?

- [ ] `25.0`
- [x] `35.0`
- [ ] `40.0`

<Explain>Окно из двух значений; последнее окно — 30 и 40, их среднее 35.0. А 25.0 — среднее всего ряда.</Explain>
</Quiz>

Лучшая неделя года закончилась 16 апреля: в среднем 14.3 тысячи в день.

Пропуски в начале можно убрать параметром `min_periods` — «считать, если в окне есть хотя бы столько
значений»:

<Demo id="min-periods" title="Неполное окно в начале" />

Первое значение — один день, второе — среднее двух, третье — трёх. Это удобно для графика, но помните: первые
точки посчитаны по меньшему числу дней и менее надёжны.

<Mistake title="окно считает строки, а не дни">
`rolling(7)` берёт семь **строк**. Если в ряду пропущены даты (дней без продаж нет в таблице), «семь строк»
окажутся восемью или девятью календарными днями. Сначала восстановите полный календарь — `reindex` или
`resample("D")`, — потом считайте окно.
</Mistake>

## Сдвиг

Метод `shift(n)` сдвигает значения на `n` шагов вперёд, оставляя метки на месте. На каждой дате оказывается
значение, которое было `n` дней назад:

<Demo id="shift" title="Сегодня, вчера и завтра" />

`shift(1)` — «вчера»: у 2 января стоит выручка 1 января. `shift(-1)` сдвигает в обратную сторону — «завтра».
В начале (или в конце) появляются пропуски: сдвигать туда нечего.

Сдвиг нужен, чтобы сравнивать ряд с самим собой в прошлом. Разность с прошлым значением встречается так
часто, что для неё есть метод `diff`:

## Рост в процентах

Разность в рублях мало говорит без масштаба: плюс 50 тысяч — это много для июля и немного для декабря.
Метод `pct_change` считает **относительное** изменение: текущее значение, делённое на предыдущее, минус
один.

<Demo id="pct" title="Выручка по месяцам и её рост к прошлому месяцу" />

−0.215 значит «на 21.5 % меньше, чем месяцем раньше», 0.189 — «на 18.9 % больше». У первого месяца
сравнивать не с чем — пропуск.

В `best_growth` — номер месяца с наибольшим ростом, в `falls` — сколько раз за год выручка упала по сравнению
с прошлым месяцем.

<Hint>`monthly.pct_change().round(3)`.</Hint>

</Exercise>

## Итоги

- `rolling(n).mean()` — скользящее среднее: итог по последним `n` значениям для каждой точки.
- В начале ряда окно не набрано — `NaN`; `min_periods` разрешает неполное окно.
- `shift(n)` — значение `n` шагов назад; `diff()` — разность с ним; `pct_change()` — относительный рост.
- Сравнивайте с тем же днём недели: `shift(7)`, `diff(7)`.
- Окно считает строки — сначала восстановите полный календарь.
