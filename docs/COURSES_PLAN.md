## Педагогика

- **Вход:** ноль по библиотеке, базовый Python (списки, словари, циклы, функции). Так написано на странице
  курса. Первый урок NumPy — «Python-минимум» с самопроверкой и ссылками, что повторить.
- **Курсы независимы: pandas проходится без курса NumPy.** Многие приходят именно за таблицами, а pandas
  прячет NumPy почти целиком: арифметика со столбцами, маски и агрегаты объясняются заново на Series, без
  массивов. Из самого NumPy курсу pandas нужно немного — `np.nan` (урок о пропусках), `np.where` и `np.select`
  (условные столбцы), тип `int64`/`float64` в `dtypes` — и это вводится там, где понадобилось. Требование
  «сначала NumPy» удлинило бы путь на 43 урока ради нескольких функций. Связь курсов задаёт поле `requires`
  в course.toml: у pandas оно пустое, поэтому проверка «понятие до объяснения» не засчитывает понятия курса
  NumPy — `np.nan` в уроке pandas обязан быть введён в `introduces` урока pandas. На странице курса pandas это
  написано в «Что нужно знать».
- **Одно понятие за раз:** короткое объяснение → демонстрация → упражнение. Длинной теории без практики нет.
- **Урок** — 10–20 минут, 3–6 упражнений (в мини-проекте — до 8).
- **Понятие не используется до объяснения.** В метаданных урока — список вводимых понятий (`introduces`);
  валидатор проверяет по коду каждого урока, что всё использованное введено в нём или раньше.
- **Повторение:** упражнения новых уроков опираются на понятия прошлых; валидатор печатает для каждого урока,
  какие старые понятия повторяются в его упражнениях.
- **Модуль** заканчивается мини-проектом на небольшом наборе данных (несколько шагов от загрузки до вывода),
  курс — итоговым проектом.
- **Типичные ошибки** объясняются там, где возникают, блоком «Типичная ошибка» и демонстрацией, которая эту
  ошибку показывает (список ниже в программах — «⚠»). Проверки упражнений ловят их и объясняют словами.
- **Язык:** русский, просто, без упрощений, которые потом придётся «разучивать». Термин при первом упоминании —
  с английским вариантом: «массив (array)». Текст свой, не пересказ документации.
- **Версии:** курс выполняется в Pyodide (NumPy 2.4.x, pandas 3.0.x), проверяется ещё и на версиях из
  `requirements-dev.txt` (NumPy 2.5.3, pandas 3.0.6). Используется только то, что есть в обеих. Возможность
  только новой версии упоминается текстом с пометкой, упражнений на ней нет.

## Ячейки и состояние

Урок — ноутбук: **одно пространство имён Python на урок**. Устройство — `src/scripts/course/lesson.ts`,
выполнение — `runtime/lesson_exec.py` (тот же код в браузере и в CPython-валидаторе).

- **Сеанс.** Воркер с Python один на вкладку; урок держит в нём сеанс: пространство имён и рабочую папку
  с копиями файлов данных (`data/`). Импортов в сеанс никто не подставляет — первая ячейка урока пишет
  `import numpy as np` сама, как в Jupyter. `courses/prelude.py` задаёт только настройки отображения.
- **Номера выполнения** `[1]`, `[2]`… как в Jupyter: видно, что выполнено в этом сеансе; `[ ]` — нет.
  Над уроком — строка состояния: «Выполнено ячеек: 5 из 11», «Выполнить всё», «Перезапустить».
- **Запуск ячейки, когда выше что-то не выполнено — автоматически.** Невыполненные ячейки выше выполняются
  сами, по порядку, со строкой «Сначала выполняются ячейки выше: 2 из 5». Спрашивать не стал: ячейки урока
  короткие, выполняются за доли секунды, а забытые ячейки выше — самая частая беда новичка в Jupyter.
  Если ячейка выше падает, запуск останавливается и ячейка показывается.
- **Пропущенное упражнение не ломает следующие ячейки.** Упражнение выше считается готовым, если его
  проверка пройдена в этом сеансе. Иначе при автозапуске: если ученик что-то написал — его код проверяется;
  не прошёл (или не написан) — выполняется **эталонное решение**, а в упражнении появляется пометка «для ячеек
  ниже выполнено эталонное решение — ваш код не изменён». Код ученика в редакторе остаётся, эталон
  не показывается.
- **«Выполнить все выше»** (кнопка у каждой ячейки) и **«Выполнить всё»** выполняют ячейки заново по тем же
  правилам. **«Перезапустить»** — новое пространство имён и исходные файлы данных; идущий запуск
  останавливается. Если Python пришлось перезапустить (зависание, нехватка памяти), урок говорит, что
  состояние сброшено, и следующий запуск снова начнёт с ячеек выше.
- **Упражнение проверяется на текущем состоянии урока:** код ученика выполняется как ячейка (печать
  и значение видны), затем проверки. Переменная из заготовки не создана или всё ещё `...` — сообщение
  «замените многоточие своим кодом», а не падение тестов. Решено — отметка сохраняется.
- **Сохранение.** Изменённый код демонстраций не сохраняется (кнопка «Вернуть»). Код упражнений —
  в localStorage (`edu:code:v1:<урок>/<упражнение>` = `{code, starter, t}`, как у задач; обновилась заготовка —
  «оставить мой код / взять новую»). Прогресс — `edu:course:v1`: решённые упражнения, отметка урока, последний
  открытый урок курса («Продолжить»). У каждой записи время изменения `t` — для синхронизации (этап 4).
- **Урок пройден**, когда решены все упражнения; отметку можно поставить и снять вручную (явная отметка
  главнее). Уроки не блокируются — порядок рекомендованный.
- **Ответ не виден до попытки.** Ответ упражнения прячется до его решения — точечно, только в разделе упражнения:
  - **Вывод демонстраций.** Скрыт сохранённый вывод демонстраций, стоящих после упражнения до ближайшего
    заголовка `#`/`##` или следующего упражнения (что раньше). Дальше идёт новый материал — он виден всегда.
    Не скрываются демонстрации `[raises]` (показ ошибки, а не ответа) и помеченные `<Demo … gate="off" />` —
    новый материал внутри раздела, с ответом не связанный. Какие ячейки скрыты, считается на сборке
    (`demoGates` в format.ts); в курсе pandas так скрыт вывод 19 демонстраций из 428 — «витрины» результата
    (`*-view` в проектах, сверки); `gate="off"` — у 16.
  - **Ответ в другом разделе** — `<Demo … gate="упражнение" />`: график или таблица, которые повторяют ответ
    упражнения выше уже в следующем разделе, скрыты до его решения (в pandas — `share-chart`, `category-chart`).
  - **Итог урока** — `<Demo … gate="lesson" />` и `<After id="*">`: итоговая демонстрация и «Выводы» проекта,
    где собраны ответы всех упражнений, скрыты до решения всех упражнений урока (или отметки «Урок пройден»).
    В pandas — 12 итоговых демонстраций и «Выводы» 14 проектов; в NumPy — 11 и 10. В NumPy по разделу упражнения
    скрыт вывод 7 демонстраций, `gate="off"` — у 5.
  - **Текст с ответом** — `<After id="упражнение">…</After>`: комментарий к результату («83 % довольных…»)
    скрыт так же. Без чисел ответа текст лучше переписать; `<After>` — когда число и есть смысл абзаца.
    Валидатор требует, чтобы упражнение `id` стояло выше. В ноутбуке — обычный текст, перед ним отдельным абзацем
    пометка «После решения упражнения выше» (для `id="*"` — «После решения всех упражнений урока»).
  - **Плашка** на месте скрытого называет упражнение: «Вывод появится, когда решите упражнение «Название»,
    — иначе он подскажет ответ. Ячейку можно и выполнить.» Кнопки: «Показать всё равно» (это место) и «Весь
    вывод урока» (всё скрытое в уроке) — до перезагрузки страницы.
  - **Открывается:** решено «своё» упражнение (отметка в `edu:course:v1`), или урок отмечен пройденным —
    в том числе вручную. Сразу, без перезагрузки, и в другой вкладке (событие `storage`). Живой вывод —
    от «Выполнить», «Выполнить всё» или автозапуска ячеек выше — виден всегда, и такая ячейка остаётся открытой
    до перезагрузки страницы (после «Вернуть» и «Перезапустить» её сохранённый вывод уже не прячется).
  - **Устройство.** `<Demo>` и `<After>` ставят `data-gate="<упражнение>"`. Встроенный скрипт страницы урока
    (до разметки, не зависит от модуля `lesson.ts`) ставит `html.gate-on`, читает прогресс из localStorage
    и через `MutationObserver` открывает решённое раньше первой отрисовки — у вернувшегося ученика плашки не
    мелькают; он же обрабатывает кнопки плашек, поэтому они работают, даже если модуль не загрузился.
    `lesson.ts` (`renderGate`) открывает скрытое при решении упражнения и отметке урока. CSS прячет
    `[data-gate]` без `is-unlocked`/`is-open` только под `html.gate-on`.
  - **Без JS всё видно:** без JS упражнение не решить — скрытое осталось бы скрытым навсегда, а урок без JS —
    учебник для чтения. Ноутбук .ipynb не меняется: вывода в нём нет.
- **Безопасность** как у задач: код выполняется только по нажатию; из адреса и ссылок — никогда.

## Интерфейс

- Вкладка «Курсы» в шапке между «Задачами» и «Справочником». `/courses` — курсы с прогрессом.
- Страница курса: для кого, что нужно знать, как устроены уроки, программа по модулям (уроки с отметками,
  «после модуля вы умеете»), прогресс, «Начать» / «Продолжить: <урок>».
- Урок: программа курса сбоку (на узком экране — выдвижная панель «Программа»), прогресс урока
  («упражнения: 2 из 4»), назад / далее, «Скачать с моим кодом» и «Скачать чистый» (.ipynb), «Урок пройден», «Нашли ошибку?» с id урока.
  В конце модуля — ссылка на практику (задачи темы, когда появятся).
- Скрытый ответ — спокойная плашка на месте вывода ячейки или текста `<After>` (название упражнения и две
  кнопки-ссылки), без рамки-предупреждения: это не ошибка, а приглашение сначала решить упражнение
  («Ячейки и состояние»).
- Ячейки различимы, но спокойно: текст — без рамки; код — рамка, заголовок, вывод; упражнение — фиолетовая
  полоса слева; вопрос — зелёная; типичная ошибка — жёлтая. Таблицы DataFrame — как в Jupyter, широкие
  прокручиваются внутри ячейки: у страницы нет горизонтального скролла на 375 px.

## Проверка — `node scripts/validate_courses.ts [курс | id урока…] [--update] [--strict]`

- **Структура:** поля course.toml / module.toml / frontmatter, id с префиксом курса и уникальный, адрес урока
  уникален, 10–20 минут (5–30 — ошибка вне), 3–6 упражнений (в проекте до 8), порядок и виды ячеек в lesson.mdx
  и lesson.py совпадают, у вопроса ровно один верный вариант, у упражнения есть условие, эталон присваивает
  переменные заготовки; ссылки на справочник (frontmatter и `/reference/…` в тексте) и на уроки существуют.
  Строгие проверки — каждый модуль заканчивается мини-проектом — у курса с `complete = true` в course.toml
  (программа написана целиком) всегда, у остальных — с `--strict`.
- **Понятия по порядку:** в коде демонстраций, эталонов и заготовок собираются понятия (`np.x`, `pd.x`,
  `.метод`, `параметр=`, оператор `@`). Имена новых столбцов в `assign(имя=…)` и в именованной агрегации
  `agg(имя=(столбец, функция))` понятиями не считаются. Каждое должно быть введено (`introduces`) в этом уроке или раньше; методы
  встроенных типов Python — известны с начала. Каждое введённое должно встречаться в коде урока.
  Ограничение: методы определяются по имени, без типа (`.sort` списка и массива — одно понятие).
  Курс с `concepts = "python"` (ООП) собирает другие понятия: конструкции `class`, `class(Base)`, каждый
  объявленный магический метод (`__init__`, `__repr__`…), декораторы `@property`, `@setter`, `@classmethod`,
  `@staticmethod`, вызовы `super()`, `type`, `isinstance`, `issubclass`, `hasattr`/`getattr`/`setattr`, `repr`,
  `hash`, `iter`, `next`, значение `NotImplemented`, операторы `raise`, `raise from`, `yield`, `is`, импорты `модуль.имя`
  (`dataclasses.dataclass`, `abc.ABC`), магические атрибуты `.__dict__`, `.__name__`. `.x` и `x=` — только чужие:
  атрибуты, методы, поля и параметры, объявленные в коде урока или прошлых уроков, понятиями не считаются.
- **Заготовка-класс:** метод класса, тело которого в заготовке — только `...`, — цель заготовки «Класс.метод»
  (кроме `@abstractmethod`). Не объявлен класс — «класс X не объявлен», метод всё ещё `...` — «метод X.m пока
  состоит из ... — допишите его» вместо проваленных тестов; эталон обязан объявлять этот метод.
- **Адреса объектов:** вывод с `at 0x…` (repr объекта без `__repr__`) — ошибка: он меняется от запуска к запуску.
- **Выполнение, в Pyodide (Node.js) и в CPython (`requirements-dev.txt`)**, каждый урок целиком, как ноутбук:
  с эталонами — всё работает, проверки проходят, вопросы с ячейкой `[quiz]` совпадают с верным вариантом;
  с заготовкой каждого упражнения (выше — эталоны) — проверка не проходит; с каждым «другим решением» —
  проходит, и все ячейки ниже работают; с каждой «ошибкой» — не проходит, причём сообщением assert, а не
  исключением. Deprecation/FutureWarning — ошибка; прочие предупреждения — только с `[warns]`.
- **Сохранённый вывод** — из Pyodide; `--update` перезаписывает output.json. Вывод CPython обязан совпадать,
  кроме ячеек `[platform]` (32-битный Python в браузере: `int32`, номера ошибок ОС).
- **Ноутбук:** экспорт с эталонами выполняется в CPython по ячейкам, как ядро Jupyter (после каждой ячейки
  фигуры matplotlib закрываются — как при inline-показе графиков): ни одной ошибки,
  ячейки с намеренной ошибкой печатают её текст, каждая проверка — «Прошло N из N».

**В браузерах:** `node scripts/validate_browsers.ts` выполняет каждый урок с эталонами в Chromium, Firefox
и WebKit (production-сборка, тот же воркер, что у страницы): проверки проходят, вывод демонстраций совпадает
с сохранённым. Уроки добавляются в проверку сами, по мере написания. Если воркер Python не запустился с первого
раза (WebKit изредка — после сотен воркеров в одной странице), проверка повторяет запуск и пишет об этом в отчёт.

**Лимит на урок — 5 минут** (`LESSON_TIMEOUT`, вместе с запуском Python и загрузкой пакетов; урок обычно идёт
секунды). Отдельные ячейки ограничены и раньше (30 с на ячейку, лимиты тестов), но зависнуть можно и там, где
таймера нет: загрузка пакетов, запуск воркера. Превысивший лимит урок останавливается (воркер завершается),
и проверка идёт дальше — один зависший урок не должен прятать ошибки в остальных. В итоге — ошибка с браузером,
уроком, последней начатой ячейкой (упражнение, демонстрация или вопрос; «запуск Python», если до ячеек не
дошло) и прошедшим временем:
`chromium: урок pd-first-table не уложился в 5 мин — остановлен на ячейке «load» (последняя начатая), прошло 300 с`;
в строке итога — «остановлено по времени: N», код выхода ненулевой. `--lesson-timeout <секунд>` задаёт свой лимит
(так проверяется сам механизм). Весь прогон в одном браузере ограничен 30 минутами; если страница проверки
упала или не уложилась, в ошибке — последние строки её журнала.

CI: задание «Курсы» (ubuntu, Python 3.14 с `requirements-dev.txt` — как Python в Pyodide: тексты встроенных
ошибок, которые показывает курс ООП, в 3.10–3.13 другие; Node 24, кэш пакетов Pyodide) и уроки в задании «Python
в браузерах». У курсов с `complete = true` строгие проверки идут всегда.

## Экспорт в Jupyter — «Скачать чистый» и «Скачать с моим кодом»

Две кнопки на странице урока. «Скачать чистый» — готовый файл с заготовками упражнений. «Скачать с моим кодом» —
тот же файл, в ячейки упражнений подставлен код из редакторов на странице (`src/lib/courses/notebook-fill.ts`,
в браузере; нерешённые упражнения остаются заготовками) — чтобы продолжить урок в Jupyter или Colab с того же
места. Валидатор проверяет подстановку: чистый ноутбук + эталоны = ноутбук с эталонами, который он выполняет.

Собирается при сборке сайта (`/courses/<курс>/<урок>.ipynb`, `src/lib/courses/notebook.ts`):

1. Заголовок и как работать с ноутбуком.
2. Скрытая ячейка «Подготовка урока» (в Colab — форма с заголовком): проверка версий (урок написан для
   NumPy ≥ 2.0 и pandas ≥ 3.0 — иначе подсказка `%pip install -U …`), файлы данных — встроены сжатыми
   (zlib + base64; `shop_orders.csv` даёт ноутбук ~60 КБ), раннер проверок и `_check(...)`.
3. Текст — Markdown-ячейки; демонстрации — ячейки кода. Ячейка с намеренной ошибкой обёрнута в `try/except`
   и печатает текст ошибки — «Run all» не останавливается ни в Jupyter, ни в Colab; упражнение — условие с подсказками в `<details>`,
   ячейка с заготовкой, ячейка проверки (тесты + `_check(test_a, test_b, names=[...])`) и решение в `<details>`;
   вопрос — варианты и ответ в `<details>`.
4. Ссылки на справочник — абсолютные (адрес production из `VERCEL_PROJECT_PRODUCTION_URL`).

Сохранённый вывод в ноутбук не кладётся — его даёт выполнение (в Jupyter будут 64-битные `int64`).

## Синхронизация через Supabase (этап 4, ветка `supabase`)

## Вес

- Код курсов (скрипт урока, стили ячеек) грузится только на страницах уроков. Редактор, воркер и Python — только
  там, где есть что запускать (уроки, задачи, статьи справочника), и не на страницах-списках. Клиент Supabase
  (этап 4) — только когда настроен и человек вошёл или открыл окно входа.
- Страница урока (сборка, gzip): HTML 11–13 КБ (с сохранёнными таблицами), скрипт урока 6,5 КБ, редактор
  CodeMirror 125 КБ (общий с задачами), воркер 15 КБ.
- Python и пакеты — с jsDelivr, в фоне, когда браузер простаивает. Холодная загрузка (пустой кэш, Chromium,
  preview на Vercel, 01.10.2026), **передано по сети / распаковано**:

  | | Передано | Распаковано |
  | --- | --- | --- |
  | ядро Pyodide (wasm, stdlib, js) | 6,25 МБ | 13,5 МБ |
  | + NumPy | 2,93 МБ | 2,96 МБ |
  | + pandas и зависимости (dateutil, pytz, six) | 4,70 МБ | 4,94 МБ |
  | **урок NumPy** всего | 9,2 МБ | 16,5 МБ |
  | **урок pandas** всего | 13,9 МБ | 21,4 МБ |

  6,2 МБ «первой загрузки» из отчёта о Pyodide — это переданный (сжатый) размер ядра; 12 МБ в первом отчёте
  курсов — несжатые файлы. Колёса пакетов уже сжаты (zip), поэтому для них цифры почти равны.
- Холодный урок, «Выполнить всё» сразу после открытия страницы: NumPy — 3,3 с (11 ячеек), pandas — 5,2 с
  (13 ячеек, включая загрузку pandas и CSV). Повторный заход — из кэша браузера.
