Объектно-ориентированное программирование (ООП) начинается не со своих классов, а с того, что вы уже знаете.
Число `150`, строка `"латте"`, список заказов, словарь меню — всё это **объекты** (object). У каждого
объекта есть **тип**, и тип определяет, что объект умеет.

## Тип объекта

Встроенная функция `type` возвращает тип значения. В выводе тип выглядит как `<class 'int'>`: тип
в Python и есть **класс** (class), а само значение — **экземпляр** (instance) этого класса. `150` — экземпляр
класса `int`, `"латте"` — экземпляр класса `str`.

<Demo id="types" title="Типы знакомых значений" />

Классы — это «чертежи», а экземпляры — сделанные по ним вещи. Экземпляров одного класса может быть сколько
угодно: `150`, `220` и `-3` — разные экземпляры `int`, но устроены одинаково.

## Тип определяет поведение

Объект — это не только данные, но и **поведение**: что с ним можно сделать. Поведение записано в классе
в виде **методов** (method) — функций, которые вызываются через точку. У строки есть `upper` и `split`,
у списка — `append` и `sort`:

<Demo id="methods" title="Методы строки и списка" />

Метод берёт данные у того объекта, у которого его вызвали: `"латте".upper()` работает со строкой
`"латте"`, а `order.append(...)` меняет именно список `order`. Методы другого класса у объекта не появятся:

<Demo id="no-method" title="У строки нет append" />

<Mistake title="AttributeError: 'str' object has no attribute 'append'">
**Атрибутом** (attribute) называют всё, что достают у объекта через точку, — и методы, и данные; подробнее
об атрибутах — в уроке о первом классе. Такая ошибка значит: у объекта этого класса нет такого атрибута или
метода. Проверьте, тот ли объект
у вас в переменной: часто вместо списка там оказалась строка (например, после `input()` или чтения файла).
</Mistake>

## Проверка типа: isinstance

Чтобы проверить, экземпляр ли значение нужного класса, есть `isinstance(значение, класс)`: он возвращает
`True` или `False`. Вторым аргументом можно передать кортеж классов — тогда подходит любой из них:

<Exercise id="numbers-only" title="Только числа">
В список `raw` попали цены из разных источников: числа вперемешку со строками и `None`. Сохраните в `prices`
только числа — и целые, и дробные, — в том же порядке.

<Hint>`isinstance(v, (int, float))` — `True` для целых и дробных чисел.</Hint>
</Exercise>

<Mistake title="type(v) == int вместо isinstance">
Сравнение `type(v) == int` пропустит дробные числа (их класс `float`), а позже в курсе — и экземпляры
классов, построенных на основе другого. `isinstance` отвечает на вопрос «подходит ли значение», и проверку
типа пишут через него.
</Mistake>

<Quiz id="bool-quiz">
Что вернёт `isinstance(True, int)`?

- [x] `True`
- [ ] `False`
- [ ] ошибку `TypeError`

<Explain>Класс `bool` построен на основе `int`: `True` ведёт себя как 1, а `False` — как 0, поэтому `True + True` равно 2. Для `isinstance` логическое значение — тоже целое число. Как один класс строится на основе другого, разберём в модуле о наследовании.</Explain>
</Quiz>

## Классы — тоже объекты

Раз всё в Python — объект, то и сам класс — объект. Его можно положить в переменную или список, передать
в функцию. А раз класс — объект, у него тоже есть тип: классы — экземпляры класса `type`, поэтому
`type(int)` — это `type`:
